# V2.3.0 本地实施与部署前检查记录

## 1. 当前状态

V2.3.0 九项宣传前核心体验范围及后台用户路线治理补充需求已完成本地代码实现。本记录只表示本地代码、数据库迁移与构建验证通过，不表示生产服务器已发布，也不替代微信真机验收。

## 2. 已实现范围

1. 官方路线与用户路线保存标准化点位、路线折线和折线来源；地图道路规划失败时使用点位虚线示意并显示风险提示。
2. 用户路线和官方路线支持受控的腾讯/高德/百度 HTTPS 路线链接。
3. 管理后台使用腾讯地图 Web JS SDK 选点、排序、删除和预览，不再要求运营人员手写折线 JSON。
4. 官方路线、公开用户路线详情启用微信分享卡片。
5. 同行支持最多 20 个途经点、地图终点、顺序调整；关联路线时保存独立快照。
6. 同行分享卡片包含标题、出发时间和当前/上限人数。
7. 首次登录进入资料完善页；发起/报名同行、公开路线前强制校验头像、用户名称、微信号或手机号、车型。手机号使用数据库唯一约束，微信号使用标准化值校验重复。
8. 历史同行支持原发起人和历史参与者再次发起，新活动不继承报名人员和原出发时间。
9. 新疆城市/地区选择器已接入同行、路线广场及关联路线选择；集合地/起点匹配优先，仅途经本地的内容次之。
10. 管理后台新增“用户发布路线管理”，支持关键词、状态、可见性和城市筛选、详情查看、管理员下架及超级管理员受控恢复；用户自行删除不可恢复，治理操作写入审计日志。

## 3. 生产配置前置条件

需要分别创建并限制两个腾讯位置服务 Key：

- `TENCENT_MAP_ROUTE_KEY` / `TENCENT_MAP_ROUTE_SECRET`：仅用于独立、可选的道路折线规划，不得打包到前端；地区归属不读取这些配置。旧 `TENCENT_MAP_KEY` / `TENCENT_MAP_SECRET` 已从配置模板及本地环境文件删除。
- `VITE_TENCENT_MAP_KEY`：管理后台 Web JS Key，只允许后台生产域名；构建时注入。

未配置后端 Key 时，保存功能仍可用，但只生成按点位顺序连接的虚线。未配置后台 Key 时，后台保留已有坐标编辑能力，但地图点击选点不可用。

生产 Compose 使用后端可选 `TENCENT_MAP_ROUTE_KEY` / `TENCENT_MAP_ROUTE_SECRET`，以及 Admin 构建参数 `VITE_API_BASE_URL`、`VITE_TENCENT_MAP_KEY`。生产配置尚需部署时核验，不代表已更新云服务器。

## 4. 数据库更新顺序

1. 备份生产 MySQL，并验证备份可恢复。
2. 部署兼容 V2.3 数据结构的后端镜像，但暂不切流。
3. 执行 `npx prisma migrate deploy`。
   本次还需应用 `20260902233000_admin_user_route_governance`，新增用户路线后台下架元数据和状态索引。
4. 执行 `npm run db:backfill:v23:preview`，保存预览报告。
5. 若 `duplicate_wechat_ids` 非空，暂停并人工合并重复账号。
6. 确认预览后执行 `npm run db:backfill:v23:apply`。
7. 再次执行 preview，核对数量及重复微信号报告。
8. 切换后端与管理后台流量，完成小程序真机回归。

回填脚本是幂等脚本，但会重建路线点位覆盖表；生产环境必须先预览、备份并在维护窗口执行。
