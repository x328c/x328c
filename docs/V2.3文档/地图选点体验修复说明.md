# 地图选点体验修复说明

日期：2026-09-03。适用：本地 V2.3 真机联调。

> 后续修订：按照用户最新要求，已改为从 `chooseLocation.address` 的明确行政区前缀自动填写地区，不能明确识别时手动确认。有效坐标不再要求地点有名称；微信原生选点直接失败时，可由用户确认进入地图自由选点。详见 [无名称选点与地址地区识别](./无名称选点与地址地区识别.md)。下文“每个点均需确认”“不解析地址”的描述仅代表上一轮实现。

## 问题与决策

真机截图显示，改用 `choosePoi` 后出现“所在位置”的 POI 列表，无法保持原来的拖动地图选点体验。本次恢复 `Taro.chooseLocation`，不尝试用样式修改微信原生列表，也不在失败时自动退回该列表。

本次优先级高于原 choosePoi 改造方案的选点交互要求；城市目录、点位地区字段、后端验证及城市筛选规则继续保留。

## 实际交互

1. 同行集合点、途经点、终点，以及路线起点、途经点、终点入口均打开微信原生地图选点。
2. 在地图上移动、搜索并确认地点。重新选择已有起终点或集合点时，传入该点坐标作为地图初始位置。
3. 地图完成后显示“确认地点所属地区”，同时展示刚选中的地点名，选择实际城市，区县可暂不确定。
4. 只有明确确认地区后才替换或新增表单点位。取消地图、取消地区确认或目录加载失败，不覆盖已保存点位。
5. 重新选点不继承旧点的城市和区县，防止跨城市移动后错误归属。首页所选城市仅作为待确认候选，不自动写入。

微信端 `chooseLocation` 的标准结果提供名称、地址及 GCJ-02 经纬度，没有城市字段。因仍不使用 Key 逆地址解析，本次以用户确认的目录代码为归属依据；不解析地址猜城市、不调用第二个选点列表，不宣称能够验证行政边界内的实际位置。

## 改动范围与兼容

- 公共选点方法改为 `chooseMapRegionPoint`，移除对 `choosePoi.type/city` 的依赖。
- 小程序 `requiredPrivateInfos` 恢复为 `getLocation`、`chooseLocation`；地理位置用途说明包含地图选点。
- 原有埋点事件名保持兼容；地图选点成功不再报告自动城市匹配成功或失败。
- 没有重新添加腾讯地图 WebService Key 或逆地址解析服务，没有更改保存接口、数据库结构和既有数据。
- 微信公众平台的接口权限和隐私保护指引需允许 `chooseLocation`；真机出现接口权限提示时应检查平台配置，不能通过业务代码绕过。此次未修改公众平台配置。

## 验证与调试

- TypeScript 类型检查通过。
- 选点/地区回归 17 项、路线列表回归 5 项、登录请求回归 8 项通过，共 30 项。
- 已检查局域网监听生成的 `dist/app.json` 与 `dist/common.js`：声明并使用 `chooseLocation`，公共业务代码不再调用 `choosePoi`。
- 调试包继续连接 `http://192.168.1.153:3000/api/v1`，不是云端。
- 自动化使用模拟原生 API，不能代替手机上的地图交互验证。需结束旧真机调试、重新编译扫码，分别测试同行和路线的所有点位入口、地图拖动、搜索、跨城市选择、取消、保存和重新编辑。
