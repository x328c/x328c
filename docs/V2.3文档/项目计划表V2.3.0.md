# 摩搭子助手 V2.3.0 项目计划

## 1. 里程碑

| 阶段 | 建议工期 | 工作内容 | 完成门禁 |
| --- | ---: | --- | --- |
| S23-0 | 1～2天 | 需求评审、地图服务确认、行政区划数据确认 | 九项核心体验及后台治理补充范围冻结，地图能力和配额可用 |
| S23-1 | 2～3天 | Prisma 迁移、地区数据、点位/快照模型 | 迁移演练可重复、旧接口测试通过 |
| S23-2 | 3～5天 | 地图适配器、路线点位/折线/外链接口 | 路线单元和集成测试通过 |
| S23-3 | 3～5天 | 用户路线、后台地图编辑器及用户路线治理 | 无需手写 JSON；用户路线可查询、下架、受控恢复并留痕 |
| S23-4 | 3～5天 | 同行点位、路线快照、再次发起 | 创建、详情、历史模板闭环通过 |
| S23-5 | 2～3天 | 城市切换、地区过滤和缓存 | 同行/路线无混城，拒绝定位可手选 |
| S23-6 | 2～3天 | 分享、资料守卫、UI收口 | 分享直达、关键操作拦截与恢复通过 |
| S23-7 | 3～4天 | 数据回填、全链路/真机/性能测试 | P0全通过，无阻断缺陷 |

以上为单人全栈的参考顺序，不是承诺日期；地图服务接入、后台编辑器和历史数据质量会显著影响工期。

## 2. 实施顺序

### S23-0：技术预研

- 确认腾讯位置服务或选定地图服务的 Web/小程序/服务端能力、域名、配额和计费。
- 验证微信真机 `openLocation`、外部链接、分享卡图片和分包详情直达。
- 固化新疆行政区划数据版本。
- 输出外链白名单和隐私政策变更清单。

### S23-1：数据库与兼容层

- 新增 UserRoutePoint、RouteRegion、UserRouteRegion、RidePoint。
- 添加 nullable 字段、组合索引和序列化兼容层。
- 生成微信号重复值报告，未处理前不开唯一约束。
- 准备点位/地区回填脚本、dry-run 和断点续跑。

### S23-2～S23-3：路线闭环

- 地区识别使用 choosePoi 城市映射与人工确认，不实现逆地理编码；道路规划、抽稀、缓存和失败重试作为独立地图能力评估。
- 用户路线改为标准点位；详情增加 polyline、导航和外链。
- 官方/用户路线分享修复。
- 管理后台上线地图编辑器，保留旧 JSON 只读排障。
- 新增后台用户路线列表、详情、下架和受控恢复接口；区分用户删除与管理员下架，治理动作写入审计日志。

### S23-4：同行闭环

- 扩展创建/详情 DTO 和行程点展示。
- 服务端根据关联路线生成不可变快照。
- 实现分享元数据和再次发起模板。
- 对历史同行和下线路线进行兼容验证。

### S23-5～S23-6：地区与资料

- 全局城市 store、选择页和列表刷新。
- 去除写死 `650100` 和城市码文本框。
- 后端资料完整度守卫、微信号规范化/唯一校验。
- 分享和资料返回意图统一处理。

## 3. 测试与发布门禁

发布前必须具备：

- Prisma validate、迁移 dry-run、备份恢复演练。
- 后端单元/集成测试、前端 typecheck、后台构建、小程序生产构建。
- 真实微信 iOS/Android：分享、选点、导航、外链、定位拒绝、资料补全。
- 新疆至少三个地州/市及两个区县的混城测试。
- 地图服务超时、无配额、非法链接、私密路线、已取消同行等降级测试。
- 列表 TP99 ≤ 300ms、详情 TP99 ≤ 200ms（不含第三方实时规划）。

## 4. 发布顺序

1. 数据库备份并部署新增表/nullable 字段。
2. 发布兼容后端，默认关闭 V2.3 feature flags。
3. 执行地区和点位回填，核对失败报告。
4. 发布管理后台并录入/复核至少三条官方路线。
   同时抽样核对公开、私密、用户删除、管理员下架四类用户路线及角色权限。
5. 发布小程序审核版本，内部/体验版真机验证。
6. 小比例开启路线折线和地区切换，再开启同行快照和资料守卫。
7. 观察至少 24 小时核心错误率与地图配额；稳定后开始公众号宣传。

## 5. 回滚策略

- 客户端：关闭 feature flags，恢复旧入口和旧字段读取。
- 后端：保持新字段兼容，不回滚已写数据；旧接口继续可读。
- 地图服务异常：关闭道路规划，保留点位与单点导航。
- 地区异常：回退到全疆/乌鲁木齐默认，但不得把不确定数据强制标为乌鲁木齐。
- 资料守卫导致大量流失：临时仅拦截发起同行，保留服务端完整度数据。
- 新表在稳定前不删除；回滚不执行 DROP。

## 6. 风险清单

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 地图配额/域名未配置 | 选点和规划不可用 | S23-0先真机验证，超时降级和配额告警 |
| 点位直连误导为道路 | 安全与信任风险 | 规划轨迹与虚线降级视觉/文案区分 |
| 历史数据缺行政区划 | 列表漏数或混城 | 离线回填、失败隔离、不默认猜测 |
| 强制资料导致流失 | 报名/发布转化下降 | 只拦关键动作，埋点观察，可单独降级 |
| 微信号无法验证 | 联系信息不真实 | 明示用户声明、唯一性仅防重复，不宣传为认证 |
| 外链带来安全风险 | 恶意跳转/审核风险 | HTTPS白名单、SSRF防护、后台下线 |
| 一次变更多模块 | 回归范围大 | 按feature flag分步上线，发布前冻结其他需求 |
| 后台误改或误恢复用户内容 | 用户数据与信任受损 | 禁止后台编辑；用户删除不可恢复；下架/恢复需角色校验和审计 |

## 7. 宣传启动条件

公众号宣传前至少满足：所有 P0 验收通过；无已知登录、分享、地图、发起、报名阻断问题；准备 5～10 条真实路线及 3～5 场真实同行；城市空状态有明确引导；监控可观察分享打开、发起、报名和资料补全漏斗。
