# 外部路线链接校验更新说明

更新日期：2026-09-04。

## 规则

外部路线链接经过 NFKC 规范化并去除首尾空白后，只要最终保存的链接字符串包含连续字符 `map` 即满足白名单要求，匹配不区分大小写。`map` 可以位于域名、路径或查询参数中。锚点会在保存前移除，因此仅在锚点中出现 `map` 不算通过，避免已保存链接再次编辑时无法通过同一规则。

示例：

- `https://maps.example.com/route`：通过。
- `https://example.com/map/route`：通过。
- `https://example.com/route?source=MAP`：通过。
- `https://example.com/route`：拒绝，未包含 `map`。

## 保留的基础安全约束

“包含 `map`”仅替代原地图服务商域名白名单，不取消 URL 安全校验：

- 仅允许合法 HTTPS URL。
- 禁止 URL 中携带用户名或密码。
- 禁止 localhost、回环、链路本地和 RFC1918 内网 IPv4 地址。
- 最大长度 1000 字符。
- 保存时移除锚点，再对最终存储值确认包含 `map`。

因此 `javascript:map()`、`http://map.example.com` 和 `https://127.0.0.1/map` 仍会被拒绝。没有新增数据库迁移或环境变量；原 `ROUTE_EXTERNAL_URL_ALLOWLIST` 不再使用。

## 影响范围与验证

用户路线新增/编辑和后台官方路线新增/编辑复用同一个 `normalizeExternalRouteUrl`，行为一致。前端及后台输入提示已同步为“包含 map 的 HTTPS 路线链接”。链接在小程序中仍只复制到剪贴板，不以内嵌网页或脚本执行。

专项覆盖了域名、路径、查询、大小写、锚点、保存后再次提交以及危险协议、本机、内网和凭证 URL；连同用户路线和后台路线服务均通过测试。
