# 摩搭子助手 V2.3.0 产品需求文档

## 1. 背景与目标

V2.2.2 已上线同行、官方/用户路线、安全手册和个人中心。首批宣传前的主要问题是：用户路线地图仅显示点位、后台官方路线录入依赖 JSON、后台无法查看和治理用户发布路线、同行缺少完整行程点、分享内容不完整、城市码写死且资料可跳过。这些问题会降低路线可信度、同行组织效率、内容治理效率和分享转化。

V2.3.0 的目标是让用户能够“选城市—看路线—查看地图—导航—按路线发起同行—分享到微信群—报名或再次发起”，并确保参与同行的用户拥有最基本的可识别资料。

## 3. 核心用户流程

### 3.1 路线浏览与导航

1. 用户选择新疆城市或地区。
2. 路线首页加载起点或途经点命中该城市的路线；起点命中优先，跨城路线显示“途经本地”标记。
3. 用户进入路线详情，地图显示起点、途经点、终点及路线折线。
4. 用户选择“导航到起点”“导航到终点”或“打开第三方路线”。
5. 第三方链接不可用时保留文字点位和单点导航，不出现空白页。

### 3.2 路线录入与分享

1. 用户填写标题并依次选择起点、途经点、终点。
2. 系统根据点位规划路线轮廓；失败时允许保存点位，但提示路线轮廓待生成。
3. 用户可填写受支持平台的第三方路线链接。
4. 公开发布前执行资料完整度检查。
5. 路线详情分享至微信后，接收者直达相同详情；私密路线仅本人可见且不得生成公开分享卡。

### 3.3 同行创建与分享

1. 用户进入发起同行；未完善资料时进入资料补全页。
2. 用户可选择一条官方或公开/本人用户路线。
3. 关联路线后自动导入路线起点、途经点、终点及轨迹摘要；集合点默认取路线起点但允许修改。
4. 用户也可不关联路线，手工选择集合点、多个途经点和终点。
5. 发布成功后可分享卡片到微信，卡片直达同行详情。

### 3.4 再次发起

1. “我的同行”在历史记录中显示“再次发起”。
2. 发起人和已报名参与者均可使用；只复制公开且当前用户有权读取的关联路线信息。
3. 进入发起页后必须重新选择未来的出发日期和时间。
4. 用户确认修改后创建新同行，原同行不变化。

### 3.5 用户路线后台治理

1. 管理员进入“路线管理”，在独立的“用户发布路线管理”区域查询公开、私密、正常、用户删除和管理员下架的路线。
2. 管理员可查看路线发布者、点位、地区、可见性、收藏/评论数、关联同行数及当前状态，不直接编辑用户内容。
3. 对违规或不适宜展示的正常路线执行下架时必须填写原因，系统记录管理员、时间、理由和操作对象。
4. 超级管理员可恢复由管理员下架的路线；用户自行删除的路线不得由后台恢复。

## 4. 详细业务规则

### 4.1 路线折线

- 点位顺序固定为一个起点、0～20 个途经点、0～1 个终点。
- 折线优先级：已保存轨迹 > 地图道路规划结果 > 点位顺序虚线降级预览。
- 虚线降级预览必须标注“仅连接点位，不代表实际道路”。
- 用户调整点位顺序或坐标后，原折线立即失效并重新规划。
- 服务端限制折线最多 500 点；保存前按距离容差抽稀，但必须保留首尾点。

### 4.2 导航和第三方链接

- “导航到起点/终点”使用微信位置能力打开单点位置。
- “打开完整路线”仅在第三方链接通过平台白名单、HTTPS、长度及格式校验后展示。
- 首期白名单由配置维护，不在代码中散落硬编码；不支持的平台显示“暂不支持直接打开，可复制链接”。
- 链接跳转前展示平台名称；后台可下线危险域名。

### 4.3 行政区划

- 首期可选范围限定新疆维吾尔自治区，使用标准行政区划码，不允许用户手填城市码。
- 同行主归属地区以集合点为准，同时为途经点建立覆盖地区索引；集合点或任一途经点命中时进入结果。
- 路线主归属地区以起点为准，同时为途经点建立覆盖地区索引；起点或任一途经点命中时进入结果。
- 选择“全疆”时返回全部新疆内容；选择城市/区县时按主归属或覆盖索引过滤。主归属命中优先排序，只有途经点命中的内容显示“途经本地”。
- “途经本地”只表达行程经过该地区，不代表同行允许途中加入；卡片和详情必须继续展示真实集合点。
- 用户拒绝定位不影响手动选择城市；定位只用于推荐当前城市，不自动覆盖用户已保存选择。

### 4.4 关联路线快照

- 同行发布时保存关联路线 ID，同时保存点位和折线快照。
- 路线后续编辑、转私密、下线或删除时，同行仍显示发布时点位快照，但不再提供原路线跳转。
- 更换关联路线前二次确认，避免覆盖已手工修改的同行点位。

### 4.5 分享

- 官方路线分享路径：`/packageRoutes/pages/detail/index?id={id}`。
- 用户路线分享路径：`/pages/routes/detail/index?id={id}`；仅公开路线允许他人访问。
- 同行分享路径：`/pages/rides/detail/index?id={id}`。
- 分享标题不得暴露微信号、精确联系方式或用户未公开资料。
- 同行分享标题建议为“{标题}｜{月日 时分}｜{当前人数}/{上限}人”；分享图使用路线封面或统一品牌图。

### 4.6 资料完整度

- 必填：用户名称、头像、车型、微信号。
- 用户名称去除首尾空格后 2～20 字；头像必须是已上传到受控 COS 的有效文件。
- 车型 1～100 字；微信号按微信号常见格式校验，忽略大小写后在未删除用户中唯一。
- 微信号为手工填写且无法自动验证，页面必须明确说明。
- 检查时机：发起同行、报名同行、公开发布路线；浏览、搜索、安全手册、保存私密路线不拦截。
- 补全成功后返回原页面并自动恢复一次原操作；取消补全则不执行关键操作。

### 4.7 再次发起

- 可复制：标题、风格、集合/途经/终点、关联路线快照、人数、速度、车型要求、说明和规则。
- 必须重置：ID、出发时间、状态、参与者、浏览量、报名数、取消/转让记录和消息。
- 已下线、被删除或无权读取的路线只复制同行点位快照，不建立新路线关联。
- 每次再次发起仍需重新确认安全协议并使用新的幂等键。

### 4.8 后台用户路线治理

- 查询条件至少包括关键词、状态、可见性和城市；关键词匹配路线标题、起点、终点或发布者昵称。
- 普通管理员和超级管理员可查询、查看详情和下架；仅超级管理员可恢复管理员下架的路线。
- 下架理由必填，长度 2～500 字；下架后路线立即退出公开列表、分享访问及新的同行关联选择。
- 用户自行删除与管理员下架共用不可用状态时，必须通过 `offlined_at/offlined_by` 区分；只有存在管理员下架记录的路线允许恢复。
- 后台不提供修改标题、说明、图片、点位、可见性等用户内容的能力，避免改变用户原始表达和所有权边界。
- 下架与恢复均写入后台操作日志，包含操作者、路线 ID、变更前后状态和原因。

## 5. 页面范围

### 小程序

- 同行首页、筛选组件、同行创建、同行详情、我的同行。
- 路线首页、官方路线详情、用户路线录入/详情、路线选择器。
- 登录后资料编辑页及关键操作拦截器。
- 新增城市/地区选择页或全局弹层。

### 管理后台

- 官方路线新增/编辑抽屉升级为地图点选、排序、路线预览和第三方链接配置。
- 路线列表增加城市/地区和外部链接状态展示。
- 新增独立的用户发布路线管理区，支持筛选、详情、下架和受控恢复，并清晰区分用户删除与管理员下架。

## 6. 非功能要求

- 路线/同行详情接口 TP99 ≤ 200ms（不含第三方地图规划）；列表接口 TP99 ≤ 300ms。
- 地图规划调用必须有 5 秒超时、失败降级和配额监控，不阻塞文字信息保存。
- 所有创建与再次发起接口必须支持幂等。
- 城市选择和地图失败不得导致页面白屏。
- 新增外链、位置和资料处理必须更新隐私政策说明及数据字典。

## 7. 成功指标

- 路线详情分享成功率 ≥ 99%。
- 关联路线发起同行时点位自动导入成功率 ≥ 98%。
- 城市切换后列表错误混城率为 0。
- 关键操作资料补全完成率作为宣传期观察指标，不预设强行通过率；需记录进入、完成、取消三个事件。
- 再次发起创建成功率 ≥ 98%，且不得复制历史参与者。
- 用户路线治理操作审计覆盖率为 100%，管理员下架后公开访问残留率为 0。
