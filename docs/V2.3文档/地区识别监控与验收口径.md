# 地区识别监控与验收口径

日期：2026-09-03。状态：客户端与服务端事件链路已实现，生产部署与观察尚未执行。

## 已实现事件

同行创建与骑友路线创建/编辑共用地区选点工具，通过现有 `/telemetry/events` 接口上报。沿用 `analytics_events`，无需新增数据库字段。

| 事件 | 触发点 | 允许属性（均可缺省） |
| --- | --- | --- |
| `poi_choose_success` | 原生选点成功返回；不代表已通过具体点位校验 | business、type、has_city、catalog_version |
| `poi_choose_failed` | 版本不支持或原生调用拒绝 | business、reason、catalog_version |
| `poi_city_map_success` | 有效具体点位城市成功映射 | business、city_code、match_type、catalog_version |
| `poi_city_map_failed` | 有效具体点位城市为空或未匹配 | business、reason、catalog_version |
| `poi_region_manual_confirm` | 用户点击确认并将地区写入表单 | business、city_code、previous_city_code、changed、district_selected、catalog_version |
| `region_submit_rejected` | 创建/保存请求返回51120～51124 | business、error_code、catalog_version |

枚举：business 为 `ride/user_route`；type 为 `1/2`，未知归为0；match_type 为 `exact/alias`；失败原因仅为 `cancel/unsupported/permission/other/empty/unmatched`。城市代码在后端还须匹配新疆目录。

`changed` 表示确认前已有城市与最终城市不同，不等同于“自动识别错误”。旧记录编辑和再次人工修改也可产生该事件。取消确认不产生已确认事件。

## 隐私和可靠性边界

- 前端显式投影字段；后端按事件再过滤。禁止存储原始 city 文本、地点名称、地址、坐标、原始错误、手机号、微信号等自由文本。
- 地区事件的 `user_id` 不写入。现有HTTP访问日志、可选JWT及限流机制仍按系统规则工作；不将其宣传为全链路匿名。
- 只发送到本项目接口，不调用微信第三方自定义分析接口，不持久化离线重试队列。
- 上报不等待业务返回，超时3秒，失败丢弃；`skipAuthRefresh=true` 防止事件失败触发刷新登录态或跳转登录。服务端沿用事件ID去重和120次/分钟限流。
- 事件是客户端观察样本，不是可信业务审计。丢包、限流、退出页面、旧客户端和伪造上报均可能影响统计，不作为用户评价或唯一发布依据。
- 原方案中的 `region_manual_correction` 是后台治理审计需求；本轮不虚构其已实现，尚需结合管理员修改权限与审计入口评审。

## 统计口径

在同一服务端入库时间窗、business和目录版本内统计：

1. 具体POI城市返回率：`poi_choose_success` 中 type=2且has_city=true的数量 / type=2数量。分母为0时显示“暂无样本”。
2. 城市映射成功率：map_success / (map_success + map_failed)。不把仅选择城市、坐标无效的返回纳入映射分母。
3. 人工确认次数及已存在城市修改比例：manual_confirm总量，以及changed=true / 带previous_city_code的manual_confirm数量。不得直接将该比例命名为自动识别错误率。
4. 地区校验拒绝次数：按error_code分组；完整接口失败率需结合HTTP请求计数，不能只用失败埋点推导。
5. 原生调用取消与权限失败单独统计，不把用户主动取消计入地图服务故障。

最小样本量、上线目标和报警阈值仍需结合体验版真机基线确定。未采集到数据不代表成功率100%。

## 运维只读查询示例

由具备只读权限的运维人员在已确认的目标数据库运行；本次没有在生产执行。统计按服务端 `created_at`，避免客户端时钟影响时间窗。

```sql
SELECT name,
       JSON_UNQUOTE(JSON_EXTRACT(properties, '$.business')) AS business,
       JSON_UNQUOTE(JSON_EXTRACT(properties, '$.catalog_version')) AS catalog_version,
       COUNT(*) AS event_count
FROM analytics_events
WHERE name IN (
  'poi_choose_success', 'poi_choose_failed', 'poi_city_map_success',
  'poi_city_map_failed', 'poi_region_manual_confirm', 'region_submit_rejected'
)
  AND created_at >= CURRENT_TIMESTAMP - INTERVAL 1 DAY
GROUP BY name, business, catalog_version
ORDER BY name, business;
```

不要导出整张事件表或增加原始POI字段来排查；未知别名通过用户主动反馈和测试复现确认，再纳入受控目录。

## 发布与验收

- 后端新增事件白名单先发布，再发布客户端；旧后端可能拒绝新事件，但客户端不得因此影响创建/编辑。
- 单元检查：事件白名单、逐事件过滤、身份字段不落库、自由文本拒绝、上报网络/同步失败不抛出、禁止登录态恢复。
- 隔离MySQL检查：`test/region-telemetry.integration-spec.ts` 实际验证脱敏JSON持久化、user_id为空、相同event_id去重。须显式指定通过隔离校验的TEST_DATABASE_URL，默认skip不算通过。
- 仍待真机验证：两类表单的取消/成功/人工确认各产生正确事件；模拟断网不影响选点表单；真实HTTP限流、鉴权、日志脱敏及生产统计查询。
- 目录版本目前随事件上报用于分析，不是强制升级协议；51124客户端目录更新重试与灰度开关仍须单独验收。
