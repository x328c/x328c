## 三、遗留问题（需你确认后再处理）

### 高优先级（涉及隐私/数据/产品口径）

1. **S-01 私密路线坐标泄露**（`ride.service.ts:935`）—— `route_snapshot` 无条件返回，私密用户路线的 title+坐标+折线会被任何查看同行的人看到。需产品定夺脱敏粒度：仅去坐标 / 标题也脱敏 / 禁止私密路线参与同行关联。
2. **S-02 用户路线响应展开泄露治理字段**（`user-route.service.ts:424`）—— `offline_reason`/`offlined_by`/`offlined_at` 会随公开接口返回。需确认无调用方依赖后改白名单。
3. **S-04 浏览量 Redis Key 无 TTL**（`ride.service.ts:254`）—— 匿名可无限刷。需产品确认计数口径（去重 vs 累加）。
4. **S-05 微信号唯一性竞态** —— 加 `@@unique` 前须先跑重复值报告处理历史脏数据。
5. **S-06 后台治理端点缺特性开关** —— 需确认运营是否接受"关开关即失去治理能力"。
6. **P-01 全疆+定位全表扫 + 分页无上限** —— 加 `@@index([status,deleted_at,departure_time])` 需迁移演练；分页上限可先加。
7. **E-01 地区目录加载失败死胡同**（`poi-region.ts:60-67`）—— 需产品定兜底策略（可重试态 vs 允许按当前城市提交）。
8. **S-03 地图 Key 类型复核** —— 确认是浏览器端 Web JS Key 而非 WebService Key，且配了域名白名单。

### 中优先级（内部重构，需回归验证）

9. R-01 两条 validateXxxRouteLink 合并；R-02 地区过滤逻辑合并；R-04 两个创建页选点逻辑抽 Hook。
10. M-01 `@Optional()` 注入改 fail-fast；M-05 治理端点改显式白名单；M-10 剔除 location_offset_seed。
11. P-02 官方路线缓存失效策略改 version key；E-10 后台表单 setFieldsValue 改 initialValues。

## 四、报告中发现的不准确项（已澄清，未按其修改）

- **R-05「matchPoiCity 无任何引用」** 不准确：`matchPoiCity` 与 `CITY_ALIASES` 被 `frontend/scripts/test-poi-region.mjs` 的 3 个测试用例引用，属**有测试覆盖的活代码**，删除会破坏测试，故**未删除**。
- **M-09「poi-region 注释与实现不符」** 不准确：注释正确说明了「`has_city` 指原生 city 字段，而非地址推断」，当前用 `chooseLocation`（无原生 city 字段）故 `has_city:false` 是诚实且一致的，**未修改**。
- **P-03「路线首页 O(n²)」** 程度被高估：实际是每页 loadMore O(n)（重建 Set），非累积 O(n²)，且路线列表规模小，收益不明确，**未修改**。
- **E-06 regions/select 的 setTimeout**：`navigateBack` 是该选择流程的既定收尾动作，加 useUnload 清 timer 反而会破坏"选完自动返回"的预期，**未修改**（仅改了 routes/create 的跳转 timer）。
