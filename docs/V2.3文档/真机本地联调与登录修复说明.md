# 真机本地联调与登录修复说明

更新日期：2026-09-03。用途：手机测试本地 V2.3 新功能，不连接云端后端。

## 问题与修复

原构建产物使用 `http://127.0.0.1:3000/api/v1`。在手机上，该地址指向手机自身，不能访问电脑上的后端；旧 development 构建监听也会持续覆盖产物。

新增 `frontend/.env.device`，当前地址为 `http://192.168.1.153:3000/api/v1`。已停止原 development 构建监听，构建并启动 device 监听。未修改 `.env.development`、`.env.cloud` 或生产配置，未部署服务器或更改业务数据。

## 调试步骤

1. 手机与电脑连接同一可互通的局域网，不使用访客隔离网络。
2. 保持电脑本地后端运行，监听 3000 端口。目前已验证局域网地址可达。
3. 微信开发者工具项目目录保持 `frontend`，小程序目录为 `dist/`。本地 HTTP 联调需要开发者工具允许不校验合法域名；此选项仅用于调试，不能代替上线域名配置。
4. 结束旧真机调试会话，重新编译并扫码连接手机，再尝试微信身份登录。
5. 电脑 IP 变化后，修改 `.env.device` 中地址并重启构建监听。

在 `frontend` 目录运行：

```sh
# 一次性构建并校验局域网目标
npm run build:weapp:device

# 持续监听本地代码，供真机调试（不要同时启动其他模式监听）
npm run dev:weapp:device -- --no-check

# 仅电脑模拟器使用回环地址时
npm run dev:weapp:local

# 正式上传前，停止调试监听，再重新构建生产包
npm run build:weapp
```

`--no-check` 跳过当前 Taro 原生环境检查器；不表示跳过类型检查和回归测试。不要上传 device 调试产物至正式版。

若手机仍无法连接，可先用手机浏览器访问 `http://192.168.1.153:3000/api/v1/regions?province_code=650000`。若打不开，检查 Wi-Fi 可达性、路由器客户端隔离、VPN 与电脑防火墙对本地后端的访问规则，不要整体关闭防火墙。电脑访问成功不能证明手机网络也可达。

## 低风险前端优化

- 登录按钮增加同步防重复提交锁，避免快速连点重复发起微信登录。
- 登录请求不携带旧访问令牌，不因 401 自动刷新并重放一次性微信 code；其他已登录接口的刷新逻辑保留。
- 网络错误区分回环地址、域名限制、证书、超时；保留业务错误信息，不输出原始敏感错误详情。
- 请求路径、参数、登录协议确认和真实微信身份登录流程未更换，失败的写请求不自动重试。
