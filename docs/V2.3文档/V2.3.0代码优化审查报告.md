## 零、总体结论

V2.3.0 代码质量整体**高于预期**。几个值得肯定的点：

- 全部 `$queryRaw` 均使用 `Prisma.sql` 模板参数绑定，**未发现 SQL 注入**
- 地区埋点的隐私投影做得扎实（`region-analytics.ts:26-38` 用正则白名单 `/^65\d{4}$/` 过滤，POI 名称/地址/经纬度均被剥离）
- 回填脚本的报告文件权限 `0600`、`databaseFingerprint()` 刻意不落库连接串，安全边界清晰
- `ride-distance-query.ts:14-21` 用 `STRAIGHT_JOIN` + 候选集 UNION 规避 OR/EXISTS 全表扫，是有意识的优化而非碰巧

发现 **34 项**可优化点。其中 **1 项属于真实隐私缺陷，建议优先处理**；**1 项属于功能卡死路径**；其余为性能、冗余与可维护性问题。

按处置方式划分：**19 项低风险可立即改动**，**15 项需进一步确认**。

## 一、安全与隐私

### S-01 【高】私密用户路线的完整坐标经 `route_snapshot` 泄露给所有访问者 **[已核验]**

**文件**：`backend/src/ride/ride.service.ts:935`、`:1112-1121`、`:1188-1190`（配合 `:1055-1059`）

**问题**：
`validateUserRouteLink` 的查询条件是 `OR: [{ visibility: 2 }, { user_id: userId }]`，即**用户可以关联自己未公开（visibility=1）的私密路线**发起同行。快照生成时把 `title`、`points`（含全部经纬度）、`polyline` 全量写进 `rides.route_snapshot`：

```ts
snapshot: {
  source_type: 'user',
  title: route.title,
  points: points as unknown as Prisma.InputJsonArray,
  polyline: polyline as unknown as Prisma.InputJsonArray,
  ...
}
```

而 `serializeRide` 第 935 行**无条件**返回：

```ts
route_snapshot: ride.route_snapshot,
```

没有任何 viewer 判断。讽刺的是，同一份响应的 `serializeRouteLink`（1188-1190 行）却做了规范脱敏：

```ts
const canExpose = route.visibility === 2 || route.user_id === viewerId;
title: canExpose ? route.title : '发起人的私密路线',
```

**结果**：同一响应里，关联路线字段正确显示「发起人的私密路线」，而 `route_snapshot` 字段把真实标题 + 所有点位坐标 + 折线原样泄露给任何查看该同行的人。这与 PRD 4.5「私密路线仅本人可见且不得生成公开分享卡」直接冲突。

**建议**：`serializeRide` 增加 viewer 判断，当快照 `source_type === 'user'` 且 `visibility !== 2 && 当前用户不是路线作者` 时，剥离 `points`/`polyline`/`title`。字段结构保持不变，**不属于接口变更**。

**预期收益**：消除私密位置数据越权读取；避免用户信任与合规风险。

**风险等级**：**高**（隐私缺陷）

**处置**：**需进一步确认** —— 需产品确认脱敏粒度（仅去坐标 / 标题也脱敏 / 还是干脆禁止私密路线参与同行关联，后者更简单也更符合 PRD）。

### S-03 【中高】后台地图 Key 进入前端产物，且 Dockerfile 用 ENV 固化进镜像层 **[已核验]**

**文件**：`admin/Dockerfile:6-7`；`admin/dist/assets/routes-*.js`

```dockerfile
ARG VITE_TENCENT_MAP_KEY
ENV VITE_TENCENT_MAP_KEY=${VITE_TENCENT_MAP_KEY}   # ← 多余且有害
```

**问题**：
1. Vite 在构建期把 `import.meta.env.VITE_*` **内联成字面量**，实际在产物中检索到明文 Key：`let n=\`7FPBZ-YFWRQ-EJL5S-25ZZ7-IMCDV-XMFBY\``
2. `ARG` 在 `RUN` 期间本就自动作为环境变量可用，`ENV` **完全多余**；而 `ENV` 会写进构建阶段镜像 config，`docker history` 可见明文，构建缓存层、CI 缓存、被 push 的中间层都会残留。

**建议**：
1. **删除 Dockerfile 第 6-7 行的 `ENV`**，只保留 `ARG`（立即生效，零风险）
2. 确认该 Key 是**浏览器端 Web JS Key** 而非 WebService Key，且在腾讯位置服务后台配置了**域名白名单 + 配额限制**

**预期收益**：消除镜像层密钥残留；浏览器端 Key 的公开属设计预期，靠域名白名单兜底。

**风险等级**：中高

**处置**：删 `ENV` 属于**低风险可立即改动**；Key 类型与白名单复核属于**需确认**。

## 二、性能

### P-01 【中】「全疆 + 定位」场景触发全表扫描，且分页无上限 **[已核验]**

**文件**：`backend/src/ride/ride-distance-query.ts:22`、`:36-37`

```ts
const from = query.city_code
  ? Prisma.sql`FROM ( SELECT id FROM rides WHERE city_code = ... UNION SELECT ride_id FROM ride_points WHERE city_code = ... ) AS candidates STRAIGHT_JOIN rides r ON r.id = candidates.id`
  : Prisma.sql`FROM rides r`;          // ← 无 city_code 时
```

**问题**：选了城市时走候选集 UNION，能命中索引（这是有意识的好设计）；但**选择「全疆」且开启定位**时退化为 `FROM rides r`，对全表逐行算 haversine。此时现有索引（`[city_code, status, departure_time]` 等）**全部以 `city_code` 打头，无法命中**。叠加 `page` 无上限、`pageSize` 可到 100，深 OFFSET 构成可用性风险。

**建议**：
1. 补 `@@index([status, deleted_at, departure_time])`
2. `page` 加 `@Max(200)`，或对 `skip` 设上限

**预期收益**：全疆浏览不再全表扫；抵御深分页 DoS。

**风险等级**：中

**处置**：加索引属**需确认**（需迁移演练）；分页上限属**低风险可立即改动**（仅收紧极端参数）。

### E-01 【高】地区目录加载失败后进入死胡同，发布流程完全卡死 **[已核验]**

**文件**：`frontend/src/utils/poi-region.ts:60-67`

