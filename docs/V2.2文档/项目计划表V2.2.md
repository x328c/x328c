## 建议执行顺序

### S22-1：冻结与审计

- 冻结 V2.1 功能新增，只接受阻断性缺陷修复；
- 全仓检索活动、论坛的路由、模块、消息、文件、埋点和 feature flag 依赖；
- 统计生产库活动、论坛、法规及关联表行数；
- 生成法规删除候选但不执行删除；
- 产物：依赖清单、候选报告、备份与恢复方案。

### S22-2：前端与后台入口收敛

- 删除小程序活动/论坛页面、路由、分包、资源、入口和历史跳转；
- 精简“我的”和路线详情；
- 管理后台移除活动/论坛页面、路由、菜单和 API；
- 产物：无残留入口的可编译版本。

### S22-3：后端下线

- 停止注册活动/论坛运行模块与调度任务；
- 清理文件、遥测、举报、通知等交叉依赖；
- 设置一个发布周期的 `410 FEATURE_RETIRED` 兼容响应；
- 保证归档表无新写入；
- 产物：路由清单、写入监控和后端测试报告。

### S22-4：法规和安全内容

- 实现法规单条/批量永久删除及审计；
- 演练关键词清理迁移，产品确认候选清单后执行；
- 复用安全指南模型发布首版安全骑行倡议；
- 简化手册页并增加倡议卡片/详情；
- 产物：迁移报告、后台操作录像或截图、内容版本记录。

### S22-5：包体优化与回归

- 开启 JS 压缩、WXML/WXSS 压缩和组件按需注入；
- 增加构建产物断言；
- 回归冷启动、分包深链、同行、安全确认、路线、评论、设置和通知；
- 产物：代码质量检测与真机报告。

### S22-6：发布

- 数据库全量备份并验证可读；
- 先发布兼容后端，再执行法规清理迁移，再发布后台和小程序；
- 发布后核对 410/404、500 率、接口延迟、法规数量和存量表写入；
- 出现误删法规、核心同行链路故障或大量旧客户端 500 时停止发布并按回滚手册处理。

## 发布门禁责任

| 门禁 | 责任角色 | 必备证据 |
| --- | --- | --- |
| 法规候选确认 | 产品负责人 | 候选 CSV/清单及抽检结论 |
| 数据备份 | 运维/开发 | 备份路径、校验值、恢复演练 |
| 安全倡议复核 | 内容录入人与另一复核人 | 来源链接、内容哈希、复核时间 |
| 接口与权限 | 后端开发/测试 | 自动化测试和路由清单 |
| 小程序代码质量 | 前端开发/测试 | 工具截图和产物配置断言 |
| 最终发布 | 项目负责人 | V2.2 验收矩阵全部 P0 通过 |

## 风险

1. 数据删除不可逆：必须在生产操作前由负责人确认备份位置和恢复演练结果。
2. 活动/论坛可能被其他模块引用：迁移前以 Prisma 外键和数据库信息架构为准生成删除顺序。
3. 按需注入可能暴露隐式全局组件依赖：须覆盖分包深链、冷启动与真机测试。
4. 旧版本仍调用已下线接口：先用 410 和升级提示过渡，并观察旧版本请求占比。
5. 活动/论坛代码与文件、遥测模块存在交叉引用：删除模块前必须先解耦公共能力。
