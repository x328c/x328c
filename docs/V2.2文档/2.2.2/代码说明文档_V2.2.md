# 摩搭子助手 V2.2 代码说明文档

> 文档版本：V2.2  
> 代码基线：2026-08-20 工作区  
> API 基础路径：`/api/v1`  
> 适用范围：微信小程序前端、NestJS 后端、管理后台及生产部署配置

## 一、项目概述

### 1.1 项目背景与定位

“摩搭子助手”是面向摩托车骑行用户的微信小程序，提供同行约骑、骑行路线沉淀与分享、骑行安全知识查询和个人资料管理能力。V2.2 将用户侧主链路收敛为“同行助手、路线、助手通知、我的”四个 Tab；历史活动与论坛功能退出运行时，但部分历史数据表仍保留在数据库中，作为归档与兼容依据。

### 1.2 核心功能模块

| 模块 | 主要能力 |
| --- | --- |
| 同行助手 | 同行列表、位置距离排序与筛选、发起同行、报名/取消报名、发起人取消或转让、成员管理、状态自动流转 |
| 路线 | 官方精选路线、用户路线录入与公开、路线广场、收藏、评论、路线关联同行、按路线发起同行 |
| 骑行安全手册 | 摩托车法规检索、法规详情与来源、安全骑行倡议、事故处理指南、安全协议确认 |
| 用户与认证 | 微信授权登录、JWT 刷新与退出、资料编辑、位置与隐私设置、我的同行/路线 |
| 助手通知 | 站内通知、未读角标、约骑相关微信订阅消息 |
| 文件服务 | 腾讯云 COS 临时凭证、图片直传、上传结果校验、文件记录 |
| 管理后台 | 用户与内容管理、官方路线管理、法规管理、安全内容发布、功能开关、审计日志 |

### 1.3 技术选型

| 层级 | 技术 | 选型说明 |
| --- | --- | --- |
| 小程序 | Taro 4.2、React 18、TypeScript 5、Zustand 5、NutUI Taro 3 | 以 React/TypeScript 统一开发微信小程序，Zustand 管理轻量全局状态，Taro 负责构建与平台适配 |
| 后端 | NestJS 10、TypeScript、Prisma 5 | 模块化服务结构、DTO 校验、统一鉴权和响应封装；Prisma 管理 MySQL 模型与迁移 |
| 数据层 | MySQL 8、Redis 7 | MySQL 存储业务主数据；Redis 用于 Token 黑名单、微信 Access Token、地理位置索引、计数及分布式锁 |
| 管理后台 | React 19、Ant Design 6、Vite 8、Zustand 5 | 独立 SPA，经 Nginx 托管在 `/admin/` |
| 部署 | Docker、Docker Compose、Nginx 1.27 | 多阶段镜像构建，内部服务不直接暴露端口，Nginx 统一处理 HTTPS 和反向代理 |
| 云服务 | 微信开放接口、腾讯云 COS/STS、腾讯云 SSL 证书 | 微信登录及订阅消息；COS 直传图片；TLS 证书用于生产 HTTPS |

## 四、核心模块说明

### 4.1 约骑模块

#### 功能描述

- 按城市、出发时间、骑行风格和当前位置筛选同行。
- 以集合地点和用户当前位置计算球面距离，先过滤、按距离升序排序，再执行分页。
- 创建者默认作为第一个参与者；支持更新、取消、转让发起人、移除成员。
- 普通成员支持报名和出发前取消报名；报名/发起需确认当前安全协议。
- 定时任务每 15 分钟将同行从报名中流转至即将出发、进行中和已结束。
- 关联官方路线或用户路线，但同一同行只能关联一种路线。

#### 核心接口

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/v1/rides` | 否 | 同行列表；支持 `latitude`、`longitude`、`radius` 等参数 |
| GET | `/api/v1/rides/nearby` | 否 | Redis GEO 附近同行查询 |
| GET | `/api/v1/rides/:id` | 可选 | 同行详情；登录后按隐私规则返回发起人微信号 |
| GET | `/api/v1/rides/:id/participants` | 是 | 参与者列表 |
| GET | `/api/v1/rides/mine` | 是 | 我发起/我加入的同行 |
| POST | `/api/v1/rides` | 是 | 发起同行，支持 `Idempotency-Key` 和安全协议凭证 |
| PUT | `/api/v1/rides/:id` | 是 | 发起人更新未开始的同行 |
| POST | `/api/v1/rides/:id/join` | 是 | 报名同行，串行事务防止超员 |
| POST | `/api/v1/rides/:id/leave` | 是 | 取消报名，受出发时间约束 |
| POST | `/api/v1/rides/:id/cancel` | 是 | 发起人取消同行并通知成员 |
| POST | `/api/v1/rides/:id/transfer-creator` | 是 | 将发起人转让给当前有效成员 |
| POST | `/api/v1/rides/:id/remove-participant` | 是 | 发起人移除普通成员 |

#### 关键业务规则

1. `min_people` 不得大于 `max_people`，出发时间必须晚于当前时间。
2. 创建、报名、转让等并发敏感操作使用事务；报名使用幂等键并校验剩余名额。
3. 距离筛选必须同时提供经纬度；`radius` 范围为 1–100 km。
4. `status`：`0` 已取消、`1` 报名中、`2` 即将出发、`3` 进行中、`4` 已结束、`5` 已下架。
5. 发起人微信号根据 `wechat_visible`、双方参与关系及用户设置决定是否返回。

### 4.2 路线模块

#### 功能描述

- `routes` 保存运营维护的官方精选路线；`user_routes` 保存用户录入路线。
- V2.2 路线首页合并展示官方路线和公开用户路线。
- 用户路线支持私密/公开、编辑、软删除、收藏、评论、图片和途经点。
- 官方路线和用户路线均可关联同行，也可从路线详情直接发起同行。
- 评论支持图片、内容哈希、幂等键、内容安全状态和后台下线。

#### 核心接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/routes` | 官方路线列表 |
| GET | `/api/v1/routes/:id` | 官方路线详情 |
| GET | `/api/v1/routes/:id/related-rides` | 关联同行 |
| GET/POST | `/api/v1/routes/:id/comments` | 官方路线评论列表/发布 |
| PUT/DELETE | `/api/v1/routes/:id/favorite` | 收藏/取消收藏官方路线 |
| POST | `/api/v1/user-routes` | 录入用户路线 |
| GET | `/api/v1/user-routes` | 我的路线 |
| GET | `/api/v1/user-routes/public` | 公开用户路线广场 |
| GET/PUT/DELETE | `/api/v1/user-routes/:id` | 详情、编辑、删除 |
| POST | `/api/v1/user-routes/:id/favorite` | 收藏用户路线 |
| GET/POST | `/api/v1/user-routes/:id/comments` | 用户路线评论列表/发布 |
| PUT/DELETE | `/api/v1/route-comments/:id` | 修改/删除本人评论 |

### 4.3 骑行安全手册

#### 功能描述

- 法规列表默认只展示现行有效且与摩托车相关的条目。
- 法规详情保留文号、适用区域、来源、版本和替代关系，不生成个案法律结论。
- 事故处理指南、安全骑行倡议由后台维护修订、复核、发布。
- 发起或报名同行前，记录用户接受的安全协议版本、内容哈希和请求 ID。

#### 核心接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/regulations` | 法规检索与分页 |
| GET | `/api/v1/regulations/:id` | 法规详情 |
| POST | `/api/v1/regulations/:id/feedback` | 法规反馈 |
| GET | `/api/v1/safety-guides/accident-handling` | 当前事故处理指南 |
| GET | `/api/v1/safety-guides/safe-riding-initiative` | 当前安全骑行倡议 |
| GET | `/api/v1/safety-agreements/active` | 按场景查询有效安全协议 |

### 4.4 用户与认证模块

#### 功能描述

- 前端调用 `wx.login` 获取一次性 code，后端调用微信 `jscode2session` 换取 `openid`。
- 首次登录创建用户和空资料；每次登录记录当前法律文档版本及哈希。
- Access Token 与 Refresh Token 使用不同密钥；刷新时旧 Refresh Token 写入 Redis 黑名单。
- 退出登录同时注销当前 Access Token，并尽可能注销对应 Refresh Token。
- 用户资料包含车型、骑龄、骑行偏好、位置、微信号及可见性设置。

#### 核心接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/auth/wx-login` | 微信登录/注册并返回用户与双 Token |
| POST | `/api/v1/auth/refresh-token` | 轮换 Access/Refresh Token |
| POST | `/api/v1/auth/logout` | Token 拉黑并退出 |
| GET/PUT | `/api/v1/users/profile` | 当前用户资料查询/更新 |
| POST | `/api/v1/users/update-location` | 更新用户位置 |
| GET | `/api/v1/users/:id` | 其他用户公开资料 |
| DELETE | `/api/v1/users/account` | 确认后注销账号 |
| GET/PUT | `/api/v1/users/me/settings` | 隐私和通知设置 |

## 五、数据库设计

### 5.1 核心表关系

```text
users 1 ── 1 user_profiles
users 1 ── N rides 1 ── N ride_participants
rides 1 ── N route_ride_links N ── 1 routes/user_routes
users 1 ── N user_routes 1 ── N route_comments
routes 1 ── N route_points / route_comments / route_favorites
users 1 ── N notifications / file_records / safety_agreement_acceptances
safety_guide_articles 1 ── N safety_guide_revisions
```

### 5.2 核心表与字段

#### `users` 与 `user_profiles`

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `users` | `id`、`openid`、`unionid`、`nickname`、`avatar_url`、`status`、`role`、`last_login_at`、`deleted_at` | 微信身份和账号主表；`openid` 唯一；删除采用 `deleted_at` 软删除 |
| `user_profiles` | `user_id`、`motorcycle_model`、`riding_years`、`riding_styles`、`city_code`、`location_lat/lng`、`wechat_id`、`wechat_visible` | 一对一扩展资料和位置/联系方式可见性 |

#### `rides` 与 `ride_participants`

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `rides` | `user_id`、`title`、`ride_style`、`departure_time`、`meetup_address`、`meetup_lat/lng`、`min_people`、`max_people`、`status`、`join_count`、`city_code` | 同行主表；`user_id` 为当前发起人；集合点坐标用于距离计算 |

#### 官方路线与用户路线

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `routes` | `title`、`city_code`、`type`、`difficulty`、`distance_km`、`duration_min`、`status`、`sort_weight`、`maintainer_id` | 官方精选路线及发布状态 |

| `route_favorites`、`user_route_favorites` | 用户 ID、路线 ID、创建时间 | 官方和用户路线分别记录收藏关系 |

| 字段 | 说明 |

## 七、第三方服务

### 7.1 微信小程序登录

1. 前端调用 `Taro.login`/`wx.login` 获取短期 `code`。
2. `POST /api/v1/auth/wx-login` 将 code 和当前法律同意凭证发送到后端。
3. 后端以 `WECHAT_APP_ID/SECRET` 调用 `https://api.weixin.qq.com/sns/jscode2session`。
4. 后端按 `openid` 创建或更新用户，只向客户端返回业务用户资料与 JWT，不返回 `session_key`。
5. 微信昵称和头像需由用户主动选择/输入，不能依赖已废弃的静默用户信息接口。

### 7.2 腾讯云 COS 文件存储

1. 客户端调用 `/files/upload-signature` 获取仅允许指定对象 `PutObject` 的 30 分钟 STS 临时凭证。
2. 客户端使用 `cos-wx-sdk-v5` 直传，支持 jpg/png/webp，单文件不超过 5 MB。
3. 上传完成后调用 `/files/callback`；后端校验对象路径归属、大小、扩展名、文件头和图片尺寸，并写入 `file_records`。
4. 长期 Secret 仅在后端；小程序只接触最小权限临时凭证。
5. 若桶采用公有读、私有写，任何持有对象 URL 的人都可读取图片；如后续涉及敏感图片，应迁移到私有桶 + CDN 回源鉴权或后端签名 URL。

微信后台至少需要配置 API 域名及 COS 域名对应的 `request`、`uploadFile`、`downloadFile` 合法域名，并设置 COS CORS。

### 7.3 微信订阅消息

- 前端在用户主动操作后调用 `requestSubscribeMessage`，不能静默代替用户授权。
- 后端通过 `SUBSCRIPTION_MESSAGE_ENABLED` 总开关及用户 `user_settings` 判断是否推送。
- 微信 Access Token 缓存在 Redis，过期前 300 秒刷新。
- 同行报名、出发、取消使用独立模板 ID；推送结果写入 `notifications.push_status`。
- 模板字段必须与微信公众平台审核通过的模板一致，变更模板后需同步环境变量和真机回归。
