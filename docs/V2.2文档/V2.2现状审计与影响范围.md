# 摩搭子助手 V2.2 现状审计与影响范围

> 审计日期：2026-08-16
> 审计对象：本地 `backend`、`frontend`、`admin`、Prisma Schema 与 V2.1 文档

## 1. 当前发现

### 活动功能

- 后端 `AppModule` 注册 `ActivityModule`，公开和管理接口均在运行。
- Prisma 存在 `Activity`、`ActivityRegistration`、`RouteActivityLink`，`Report.activity_id` 也引用活动。
- 小程序主包包含活动列表、详情、创建和“我的活动”；首页和路线详情均有活动入口。
- 安全协议包含 `activity_create`、`activity_register` 两个场景。
- 管理后台通过通用管理 API 提供活动列表、下架和删除。

结论：不能只删除前端按钮；必须同步清理模块注册、通知/举报跳转、路线关联及安全协议入口，否则仍可通过旧链接或 API 使用。

### 论坛功能

- 后端 `ForumModule` 包含公开 API、后台审核、限流、审核任务和多项守卫。
- `TelemetryModule`、`FileModule` 直接导入论坛模块，删除前需要先解耦公共依赖。
- Prisma 存在版块、帖子、图片、回复、点赞和用户限制模型，`User`、`AdminUser`、`FileRecord` 均有论坛关系。
- 小程序支持可选 5 Tab 论坛以及 `packageForum` 分包；管理后台存在论坛审核页面和路由。

结论：论坛删除是跨模块改动；历史数据和媒体文件先归档，避免在代码下线时混入未经确认的数据销毁。

### 骑行安全手册

- 当前页面有类别按钮、城市码输入和状态按钮三组筛选；默认查询 `status=2`。
- 页面已有“骑行应急知识”卡片，适合在其上方增加“安全骑行倡议”。
- 后端已有版本化 `SafetyGuideArticle` / `SafetyGuideRevision` 及创建、复核、发布、下线后台流程，可直接承载倡议。

### 法规后台

- 现有后台已支持单条创建/修订/复核/发布/失效/替代/下架和最多 100 条批量工作流。
- 尚无永久删除或批量删除接口；表格已经存在跨分页选择，可复用为批量删除选择状态。
- `RegulationFeedback` 对法规无级联删除，`RegulationImportRow.regulation_id` 也需要先处理，不能直接删除主记录。

### 小程序代码质量

- `frontend/project.config.json` 当前 `setting.minified=false`，因此“JS 文件压缩”检测不通过符合现状。
- `minifyWXML=true`、`minifyWXSS=true` 已开启。
- 源配置和生成配置尚无 `lazyCodeLoading: "requiredComponents"`，因此“组件按需注入”检测不通过符合现状。

## 2. 风险分级

| 风险 | 等级 | 控制措施 |
| --- | --- | --- |
| 法规关键词规则误删 | 极高 | 候选导出、人工抽检、全量备份、事务删除 |
| 活动/论坛交叉依赖导致编译失败 | 高 | 先解耦公共模块，再移除注册，逐层构建 |
| 旧客户端继续调用下线 API | 高 | 一个发布周期的 410 与升级提示、监控请求占比 |
| 按需注入后分包组件缺失 | 中 | 冷启动、深链、真机与分包逐页回归 |
| 历史通知跳转失效 | 中 | 历史类型降级为无跳转通知 |
| 倡议被误解为法规或免责 | 中 | 明确内容性质、来源、版本和免责声明 |

## 3. 实施结论

V2.2 应拆成四个可独立验证的变更组：功能下线、法规数据治理、安全倡议、包体优化。法规永久删除不得与代码下线合并成不可审阅的大迁移；生产执行前必须单独确认候选数量和备份。
