# 摩搭子助手 V2.2 技术方案设计

## 1. 删除策略

本次是功能层面的破坏性版本升级。发布前导出生产数据库备份并记录表行数；移除 Nest `ActivityModule`、`ForumModule`，并清理其在文件、遥测、管理端和小程序路由中的依赖。活动与论坛历史表本次只读归档，不执行 `DROP TABLE`，避免扩大到需求未授权的数据销毁。旧 API 由统一下线控制返回 `410 Gone` 和升级提示一个发布周期，之后再移除路由。

需要移除的运行时依赖包括：活动控制器/服务/DTO/任务、`RouteActivityLink` 创建逻辑、活动通知跳转、活动协议场景入口；论坛控制器/服务/守卫/审核任务、遥测和文件模块中的论坛依赖、后台审核路由。`activity_create`、`activity_register` 的历史安全确认记录继续保留，但不再发布新协议版本。若未来物理清表，必须另行处理 `reports.activity_id`、活动报名、路线关联、论坛文件记录和用户限制等依赖。

## 2. 法规永久删除

迁移使用 SQL 条件：`title`、当前修订（无当前修订时取最新修订）的 `summary`/`content`、关联 `tags.name` 均不含“摩托车”时删除该法规。先将命中 ID 和标题导出为报告，再把 `regulation_import_rows.regulation_id` 置空、删除 `regulation_feedbacks`，最后删除法规；由外键级联清理修订、标签链接和区域。删除后清理无引用标签。SQL 必须使用 `NOT LIKE '%摩托车%'` 并显式 `COALESCE`，避免 `NULL` 导致三值逻辑漏删。

## 3. 后台法规删除接口

| 接口 | 权限 | 行为 |
| --- | --- | --- |
| `DELETE /api/v1/admin/regulations/:id` | 超级管理员 | 永久删除单条法规；请求体必须包含 `reason` |
| `POST /api/v1/admin/regulations/batch/delete` | 超级管理员 | 接收不重复的法规 ID 和原因；原子删除，返回数量与 ID |

服务端在事务中查询目标、把导入行引用置空、删除关联反馈后删除法规，写 `operation_logs`。找不到 ID、重复 ID、空原因或角色不足均失败且不产生部分删除。批量最多 100 条，并对 ID 去重；审计摘要保存标题、文号和删除数量，不保存法规全文。

## 4. 安全骑行倡议

复用现有 `SafetyGuideArticle` / `SafetyGuideRevision`，新增固定 `code=safe_riding_initiative`，不再创建平行内容表。`content_json` 使用 `{ sections: [{ title, paragraphs, bullets }], sources: [...] }`；既有创建、复核、发布、下线及操作日志链路继续使用。扩展公开接口为 `GET /api/v1/safety-guides/safe-riding-initiative`，后台仍通过 `/api/v1/admin/safety-guides` 管理。首版内容围绕头盔护具、驾照与车辆状态、限速守法、不酒驾/疲劳骑行、天气路况、车队纪律、事故处置和文明骑行，且明确以道路交通法规和官方安全提示为准。

## 5. 小程序构建优化

在 Taro 源配置中加入 `lazyCodeLoading: "requiredComponents"`，确认生成的 `dist/app.json` 顶层仍保留该字段。仅声明实际使用的页面组件，避免在 `app` 全局注册低频组件；法规、法律和路线继续使用分包。开发者工具 `project.config.json` 与可提交的项目配置启用 `setting.minified=true`、`minifyWXML=true`、`minifyWXSS=true`，生产构建同时保持 Vite minify，避免只依赖上传阶段压缩。每次构建后以脚本断言配置和产物，不以人工勾选作为唯一证据。

启用按需注入后，未访问页面与非当前页声明组件不会初始化，因此必须执行深链路、分包、弹窗和安全确认回归。依据：[微信按需注入说明](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/lazyload.html)、[微信社区“JS 文件压缩”检测说明](https://developers.weixin.qq.com/community/develop/doc/00040e5a0846706e893dcc24256009)、[微信示例项目配置](https://github.com/wechat-miniprogram/miniprogram-demo/blob/master/project.config.json)。

## 6. 测试与回滚

- 单元：删除权限、批量参数校验、倡议状态转换。
- 集成：迁移前后法规计数、前台只读取已发布倡议、删除法规后搜索为空。
- 小程序：冷启动、4 Tab、路线、同行、设置、手册、倡议详情、真机调试。
- 回滚：代码可回滚；数据删除不可通过代码反向恢复，只能从上线前备份恢复。因此生产迁移必须经预发布演练和人工确认。

## 7. 代码影响清单

- 后端：`app.module.ts`、activity/forum 目录、file/telemetry 对论坛的导入、admin 活动接口、协议场景常量及相关测试。
- 小程序：`app.config.ts`、首页活动 Tab、活动页面、论坛页面/分包、路线详情“发起活动”、个人页和历史消息跳转。
- 管理后台：路由、侧边栏、活动管理、论坛审核页面/API/type；法规页新增危险操作；安全治理页支持倡议 code。
- 数据：仅法规清理迁移会永久删除业务数据；活动/论坛模型保留为归档表，Prisma 是否保留模型取决于后台审计读取需求，运行时模块不得写入。
