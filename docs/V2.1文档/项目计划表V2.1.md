## 2. S21-0：基线与评审（W1）

| ID | 工作 | 交付/验收 |
|---|---|---|
| B01 | V2.0 基线审计 | 三端版本、Prisma、迁移、功能开关和未提交改动清单 |
| B02 | 术语冻结 | “同行助手/骑行安全手册/安全知识”的替换与禁止替换清单 |
| B03 | 路线联动规则 | 城市冲突、路线更新/下架、快照和修改边界签字 |
| B04 | 评论治理评审 | 审核供应商、人工队列、举报 SLA、只读/关闭方案 |
| B05 | 内容复核 | 事故指南逐条对应官方来源，确认 2026 修改动态 |
| B06 | 法律评审 | 协议有效性、显著提示、未成年人、平台/组织者角色和隐私最小化 |

M0：未取得内容和法律评审时，可继续开发默认关闭的技术骨架，但不得开启指南发布和强制协议开关。

## 4. S21-2：路线联动（W3-W4）

### 后端

- L01：扩展同行/活动创建 DTO，服务端校验路线状态和城市；
- L02：事务内写业务、路线关系、协议确认和派生计数；
- L03：同行/活动详情返回最小路线摘要，路线关联查询只返回有效业务；
- L04：缓存写后失效、并发/幂等和越权测试。

### 小程序

- L05：路线详情“按此路线发起”动作面板；
- L06：同行/活动创建页复用路线选择器和登录回跳；
- L07：详情关联路线卡片、地图失败降级及下架状态；
- L08：埋点端到端入库和两条纵向 E2E。

M2：完成“路线 → 发起同行 → 确认 → 详情”和“路线 → 发起活动 → 另一用户报名”；原无路线发布路径无回归。

## 9. 发布与灰度顺序

1. 备份并校验测试/生产数据副本；
2. 执行 V2.1 增量迁移演练，生产执行需用户另行明确授权；
3. 部署后端且新增开关保持关闭；
4. 部署管理后台，导入指南/协议草稿并完成双人复核；
5. 构建小程序 4 Tab 和 5 Tab 候选包，论坛资质未确认时只发布 4 Tab；
6. 内部账号开启路线联动；
7. 开启协议强制前检查最低客户端版本覆盖率；
8. 评论先只读验证，再对白名单开放写入；
9. 事故指南通过内容和法律复核后开启；
10. 10% → 30% → 全量，每阶段守护指标连续达标后扩大。

未经明确授权，不部署生产、不执行生产迁移、不提交小程序审核、不自动 commit/push。

## 10. 回滚顺序

1. 关闭 `route.comment_enabled` 和 `route.link_enabled`；
2. 视情况保留评论只读或关闭 `route.comment_read_enabled`；
3. 关闭 `safety_guide.enabled`；协议异常时停止相关写入口，不能绕过确认继续放行；
4. 清理 V2.1 Redis Key；
5. 回滚应用版本，保留新增表和确认/审计记录；
6. 验证 V1 登录、同行发布/报名、活动和通知恢复；
7. 形成事件记录和前滚修复计划。

## 11. Go 条件

- P0/P1 缺陷清零；
- 空库和 V2.0 数据副本迁移、备份、失败恢复/前滚通过；
- 事故指南与协议完成内容、法律和双人复核；
- 评论审核、举报和只读/关闭演练通过；
- 4/5 Tab 构建、三端检查和 V1/V2.1 E2E 通过；
- 监控、运营、内容和值班负责人已就位；
- 所有外部写操作另获用户明确授权。

任一条件不满足时结论为 No-Go 或关闭相应开关后的缩范围发布。

## 12. 主要风险

| 风险 | 触发条件 | 应对 |
|---|---|---|
| 安全确认被误解为免责 | 文案绝对免责或提示不显著 | 法律复核；改为风险告知；保留依法责任 |
| 事故规定更新 | 正式修订发布或来源失效 | 复核提醒；先下架摘要；更新修订后再发布 |
| 评论审核积压 | 超时率/积压超过阈值 | 关闭写入、保持待审、人工补偿 |
| 名称迁移破坏契约 | API/表/官方标题被替换 | 用户文案白名单；自动扫描；V1 回归 |
| 路线下架破坏业务 | 详情只依赖实时路线 | 保留业务快照；关系显示失效不删除业务 |
| 设置成为假功能 | 开关无法回读或系统权限误报 | 每项端到端验收；未实现则明确说明而非假开关 |
