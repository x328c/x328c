# 摩搭子助手 V2.1 UI/UX 设计思路

## 1. 设计目标

V2.1 以“路线发现 → 发起/加入同行 → 安全确认”为主线。设计应减少重复填写，同时明确路线信息、用户组织活动和平台服务之间的边界。

原则：

- 先安全、后转化：安全确认清晰可读，不使用默认勾选、弱化文字或诱导按钮；
- 真实可用：设置项和权限状态必须对应真实能力；
- 名称友好、事实准确：用户入口改为“同行助手”“骑行安全手册”，官方文件仍保留正式名称；
- 状态完整：加载、空、失败、未登录、下架、审核中、驳回、功能关闭和弱网都有明确反馈；
- 保持 V2.0 Token、StatePanel、SourceBlock、ConfirmDialog 和登录回跳规则，不另建割裂的视觉体系。

## 2. 信息架构与名称

### 2.1 Tab

4 Tab 构建：**同行助手、路线、助手通知、我的**。
5 Tab 构建：**同行助手、路线、论坛、助手通知、我的**。

默认入口仍是原 `/pages/index/index`，不移动路由、不改变原生 Tab 数量的构建时方案。论坛资质或开关不满足时继续使用 4 Tab。

原“约骑”Tab 图标替换为摩托车轮廓：

- 普通态使用中性灰，选中态使用品牌橙；
- 图形以侧视摩托车为主，避免与汽车、路线定位、头盔图标混淆；
- 普通/选中两张本地 PNG 尺寸一致、透明背景，不使用网络图片；
- 4/5 Tab 均真机检查文字宽度、不同系统字体、安全区和角标；
- 图标带等价无障碍语义“同行助手”。

### 2.2 术语层级

- 一级产品名：骑行安全手册；
- 内容集合泛称：安全知识；
- 内容类型/来源元数据：法律、行政法规、部门规章等正式名称不改；
- 正文提示：“内容仅作安全知识与官方信息索引，请以来源机关发布的现行原文为准。”

禁止机械全局替换“法律/法规”，应建立可审查清单处理页面标题、按钮、分享文案、空状态、通知、埋点显示名和无障碍标签。

## 3. 路线与同行/活动联动

### 3.1 路线详情

信息顺序：地图/点位 → 核心参数 → 安全提示 → 路线分段 → **按此路线发起** → 路线评论 → 相关同行/活动 → 来源与维护信息。

“按此路线发起”使用固定底部主按钮，点击后弹出轻量动作面板：

- 主选项“发起同行”；
- 次选项“发起活动”；
- 说明“将带入路线和起终点，时间、集合地点等仍需确认”；
- 路线已下架或联动关闭时不显示可点击假按钮，使用 StatePanel/说明条替代。

### 3.2 创建页路线选择器

在标题字段之后放置“关联路线（可选）”：

- 未选：虚线卡片“选择官方路线”；
- 已选：封面、名称、城市、难度、里程、起终点，并提供“更换”“移除”；
- 从路线详情进入时自动选中，但不自动提交；
- 预填字段使用“已根据路线填入”辅助文案，用户修改后显示“已自定义”；
- 城市冲突使用阻断式行内错误，明确让用户选择保留哪个城市；
- 地图失败显示点位文字，不丢失选择。

### 3.3 详情回链

同行/活动详情在集合信息后展示“关联路线”卡片。路线下架时展示灰色不可跳转卡片“原关联路线已下架，活动信息仍以本页为准”，不得把业务详情整体判为失效。

### 3.3 用户路线

路线首页提供“路线广场、我的路线、录入路线”三个入口。录入页使用微信地图选点完成起点、终点和途经点，支持 1—5 星难度、最多 6 张图片及私密/公开可见性。选择“发布平台”时常驻点位公开提示，提交前再次确认。

“我的路线”按全部、仅自己可见、发布平台分栏；“路线广场”支持关键词、难度和最大里程筛选。详情页展示地图、参数、图片、浏览/收藏数据，创建者可编辑和删除；公开详情复用评论图片、预览、举报和本人删除能力。

## 4. 路线评论

### 4.1 公开区

标题为“骑友评论”，标题右侧不在 P0 堆叠计数。评论按发布时间和 ID 稳定排序，卡片展示头像、昵称、发布时间和纯文本正文。

状态：

- 游客：可读，输入区提示登录后评论；
- 空：说明“还没有公开评论”，不暗示无人骑过；
- 举报：评论保持公开，不向用户展示审核状态；
- 删除：管理员核实后删除，公开区不再返回该评论；
- 写入关闭：保留只读列表时显示“评论暂时只读”；读写均关闭时隐藏内容并显示统一关闭状态；
- 弱网：保留已加载列表，局部重试，不清空页面。

### 4.2 输入与防重复

- 点击输入区打开半屏编辑器，2-500 字，显示计数；
- 支持最多 2 张图片，不支持外部链接、评分或回复；
- 提交按钮在请求中禁用，客户端生成幂等键；
- 成功后就地显示已发布评论，统一提示“评论已发布”；
- 非本人评论右下角显示“举报”，确认后提示“举报已提交”；
- 已删除评论不进入公开列表。
- 举报在评论更多菜单中，原因必选，可补充说明，提交后显示单次结果。

## 5. 骑行安全手册

### 5.1 首页

页面标题“骑行安全手册”，副标题“官方信息索引与骑行安全知识，不提供个案结论”。

顶部搜索之后增加横向重点卡片：

**骑行应急知识**
“发生事故先确保安全，快速查看报警、取证、协商与复核提示”
按钮：“查看指南”

卡片使用警示黄的浅色背景和深色文字，不能使用错误红营造紧急按钮错觉。它不是报警功能，不展示会被误认为一键报警的电话按钮。

### 5.2 骑行应急知识页

页面采用任务式而非法规长文式结构：

1. 顶部声明和“人员受伤/死亡、疑似酒驾、无证、逃逸等应立即报警”提醒；
2. “先做什么”编号步骤；
3. “哪些情况不要自行协商”醒目卡片；
4. “现场取证清单”勾选式阅读列表（只作阅读，不上传事故资料）；
5. “认定、复核与赔偿途径”时间轴；
6. SourceBlock 展示官方文件、公安部、施行日期、最后复核和官方原文；
7. 底部“内容有误/来源失效”反馈。

固定提示：“如有人身危险，请优先联系 110/120 并服从现场人员指挥。本指南不判断事故责任，不替代公安交管、保险机构或专业法律意见。”

来源不可访问时显示“官方链接暂时无法打开”，仍保留标题、机关和 URL 复制能力。内容超过复核期时在顶部展示“规则可能已更新，请优先查看官方原文”。

## 6. 安全须知确认

用户界面名称采用“安全须知与风险提示”，不使用“平台免责协议”作为唯一标题。

### 6.1 两段式弹窗

第一层为摘要确认弹窗：

- 本次动作和对象，例如“加入：周末南山同行”；
- 5 条高风险摘要：交通与骑行风险、能力/车况、遵守规则、非专业组织与救援、依法承担责任；
- “查看完整内容”链接；
- 未预选的确认框；
- 次按钮“暂不参加”，主按钮“确认并继续”。

点击完整内容进入可滚动协议页，显示版本、发布日期和最近法律复核时间。重大利害关系条款使用标题、加粗和足够对比度提示，但不使用全屏红色或强迫倒计时。

### 6.2 交互规则

- 每次发起或报名均确认，不能用历史全局勾选直接跳过；
- 用户关闭弹窗时保留表单，不提交业务请求；
- 协议在弹窗打开期间切版，提交时提示“内容已更新，请重新确认”；
- 弱网加载失败时禁止提交并提供重试，不能用本地旧协议兜底放行；
- 确认成功但业务失败时展示业务错误；重试使用同一幂等上下文，避免重复报名；
- 字号缩放后关键条款、确认框和按钮不得截断，点击区域至少 44 CSS px 等效尺寸。

## 7. 设置页

设置页从简单文本列表升级为分组列表，每项含标题、当前状态/说明、箭头或真实开关。

### 7.1 页面结构

1. 账号与安全：账号状态、退出登录、注销说明；
2. 隐私：资料可见范围、联系方式展示、个人信息清单、隐私政策；
3. 通知：同行、活动、系统通知偏好；系统通知权限展示“已开启/未开启/未知”；
4. 系统权限：定位、相机、相册，点击跳转小程序设置；
5. 内容与帮助：意见反馈、安全须知、用户协议、隐私政策、骑行应急知识；
6. 存储与版本：缓存大小、清理缓存、版本号、4/5 Tab 构建标识；
7. 关于摩搭子助手。

### 7.2 状态和反馈

- 服务端偏好开关采用乐观显示但失败立即回滚，并在行内说明；
- 系统权限不可用时说明如何开启，不循环弹授权框；
- 清缓存二次确认并列出“不会清除账号登录和待发布草稿”；
- 意见反馈限制长度和图片类型，提交中防重复；
- 注销流程未实现时进入说明页，不能展示可点击后无结果的按钮；
- 所有列表项设置稳定 `key`、可见焦点和读屏标签。

## 8. 视觉与组件复用

- 继续使用 V2.0 品牌橙作为主操作色，成功/警告/错误保持语义色；
- 新增 `RoutePickerCard`、`RouteLinkCard`、`SafetyAgreementDialog`、`SettingsSection`；
- 复用 `StatePanel`、`SourceBlock`、`ConfirmDialog`、`StatusTag` 和 `Skeleton`；
- 评论审核状态复用论坛的状态文案规范，但组件样式不依赖论坛分包；
- 事故指南正文行高不低于 1.65，长段落拆成步骤和清单；
- 页面底部固定操作适配 `safe-area-inset-bottom`。

## 9. 设计验收

- 4/5 Tab、普通/大字体、iOS/Android 至少各一台真机通过；
- 从路线进入两类创建页，返回后仍保留原路线详情位置；
- 四个安全确认场景的正常、取消、切版、弱网和过期状态齐全；
- 评论的公开/本人审核状态不会混淆；
- 名称扫描覆盖导航标题、分享、消息、空状态、设置、无障碍与埋点显示名；
- 官方标题没有被“安全知识”替换；
- 设置页不存在不生效的假开关；
- 关键任务 5-8 人可用性测试完成率目标不低于 90%。
