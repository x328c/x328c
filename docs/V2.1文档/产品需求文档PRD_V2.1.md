# 摩搭子助手 V2.1 产品需求文档

> 版本：Draft 1.0
> 日期：2026-08-08
> 依赖：[V2.1 技术方案](./技术方案设计V2.1.md) / [UI/UX](./UI_UX设计思路V2.1.md) / [项目计划](./项目计划表V2.1.md)

## 1. 目标与成功标准

V2.1 的目标是让用户从“发现路线”自然进入“发起或参加同行”，同时提升安全知识可达性、风险告知质量和设置页完整度。

发布后观察以下指标，具体阈值在开工审计时以 V2.0 最近 14 天基线校准：

- 路线详情到发起同行/活动的转化率；
- 绑定路线的同行/活动占新建总量的比例；
- 路线评论举报率、待审核积压、平均处置时长和屏蔽率；
- 安全确认弹窗到提交成功的完成率，不以诱导勾选提升转化；
- 骑行应急知识打开率、官方来源点击率和内容反馈率；
- 设置项任务成功率及因名称迁移导致的用户求助量；
- V1 登录、发布、报名和通知成功率不得显著下降。

## 2. 版本范围

### 2.1 P0

| ID | 模块 | 需求 |

| LINK-01 | 路线联动 | 发起同行助手或活动时可选一条已发布路线并建立服务端关系 |
| LINK-02 | 路线联动 | 路线详情可直接发起同行助手或活动，预填路线及起终点信息 |
| LINK-03 | 路线联动 | 同行/活动详情展示所绑定路线入口；路线下架后展示失效状态但不删除既有业务记录 |
| CMT-01 | 路线评论 | 登录用户可提交一级评论并立即公开，每条最多附 2 张图片，可删除本人评论 |
| CMT-02 | 路线评论 | 用户可举报评论；3 个不同用户举报后自动进入待审核，后台可通过或屏蔽 |
| URT-01 | 用户路线 | 登录用户可录入、编辑、软删除自己的骑行路线，并选择“仅自己可见”或“发布平台” |
| URT-02 | 路线广场 | 公开路线可被搜索、按难度和里程筛选、查看、收藏和评论；私密路线仅创建者可访问 |

| NAME-02 | 名称迁移 | 用户侧“法规检索”改为“骑行安全手册”，通用入口文案改为“安全知识” |
| GUIDE-01 | 事故指南 | 骑行安全手册首页增加“骑行应急知识”，展示版本化内容和官方来源 |
| SAFE-01 | 安全确认 | 发起、报名同行助手和活动前，必须逐次确认当前版本安全须知 |
| SET-01 | 设置 | 隐私、通知、系统权限、意见反馈、协议与关于、缓存、退出登录可实际使用 |

### 2.2 P1

- 路线详情展示绑定的有效活动摘要；
- 用户可管理自己的路线评论；
- 设置页增加账号注销申请及冷静期流程；
- 事故指南内容纠错反馈进入后台队列；
- 运营后台支持指南版本发布、失效和复核提醒。

### 2.3 明确不做

- 本期支持用户手工录入路线和地图选点；不做 GPX/KML 导入、实时导航、轨迹记录、轨迹附近搜索或路线评分；
- 不做评论回复、楼中楼、评论图片、匿名评论、评论排序算法或点赞；
- 不把“同行助手”扩展成即时通讯、位置共享或救援调度工具；
- 不生成事故责任、赔偿金额、违法认定或法律结论；
- 不因名称迁移批量重命名数据库表、Prisma 模型或既有 API；
- 不用一份安全确认替代必要的安全措施、内容治理、保险建议或法定责任。

## 3. 核心用户流程

### 3.1 从路线发起同行助手/活动

1. 用户打开已发布路线详情；
2. 点击“按此路线发起”，选择“同行助手”或“活动”；
3. 未登录时保存 `returnUrl` 和 `routeId`，登录成功后返回创建页；
4. 创建页展示已选路线卡片，并预填起点、终点、城市和路线摘要；
5. 用户仍需填写时间、人数、集合地点等业务必填项；
6. 提交前打开安全须知弹窗，用户阅读并主动确认；
7. 服务端在同一事务中创建业务记录、路线关系和安全确认记录；
8. 成功页提供“查看同行/活动”和“返回路线”入口。

异常规则：

- 路线已下架、软删除或开关关闭：阻止新绑定，保留用户已填写内容并允许移除路线后继续创建；
- 路线在用户填写期间发生更新：服务端以提交时状态为准，返回明确冲突并要求重新确认；
- 地图失败：仍显示文字点位和预填字段；
- 路线城市与用户选择城市不一致：要求用户明确选择，不静默覆盖。

### 3.2 在同行助手/活动创建页选择路线

- “选择路线”为可选项，不阻断原有无路线发布；
- 仅查询已发布、未删除且 `route.enabled=true` 的路线；
- 选择后展示路线名称、城市、难度、里程及起终点；
- 用户可更换或移除；已选路线不可由客户端伪造标题或点位；
- 创建成功后由服务端建立唯一关系，重复提交通过幂等键返回同一结果。

### 3.3 报名与安全确认

- 点击“立即报名”后先展示业务信息摘要，再展示不可预勾选的安全确认；
- 用户必须打开全文或滚动至提示区，并点击“我已阅读并确认”；
- 弹窗必须突出骑行风险、遵守交规、身体和车辆状况、组织者非专业救援、平台责任边界及紧急处理；
- 服务端校验协议 ID、版本、适用动作和内容摘要，不接受仅由客户端传来的 `agreed=true`；
- 重复报名保持幂等，不重复生成有效参与记录或虚增计数。

### 3.4 路线评论

- 入口位于路线详情内容之后、相关同行之前；
- P0 仅支持 2-500 字纯文字一级评论；
- 提交后立即发布；基础敏感内容检测命中时仍可见，但标记为“待审核”并进入人工队列；
- 同一用户对同一评论只能举报一次；累计 3 个不同用户举报后自动标记“待审核”；
- 管理员可将评论通过为“正常”或处理为“已屏蔽”；已屏蔽评论不进入公开列表；
- 用户可在“我的评论”看到审核中、驳回、已公开、已下架和已删除状态；
- 用户只能删除本人评论；已屏蔽评论不可编辑；
- 举报必须校验评论存在并记录证据，管理员通过/驳回/下架必须填原因并写审计日志；
- `route.comment_enabled=false` 时关闭提交入口和写 API，公开只读是否保留由独立 `route.comment_read_enabled` 决定。

### 3.5 骑行安全手册与骑行应急知识

骑行安全手册首页的信息层级：

1. 搜索安全知识；
2. 高频任务卡片；
3. “骑行应急知识”醒目但不制造恐慌的快捷入口；
4. 安全知识分类与最近复核提示。

骑行应急知识页面必须展示：

- 首要安全与报警判断；
- 可自行协商的财产损失事故处理步骤；
- 现场取证清单；
- 认定、复核和损害赔偿途径的流程提示；
- “不判断责任、不替代交警/保险/专业意见”声明；
- 官方文件名称、发布机关、施行日期、最后复核时间和明确的官方原文链接；
- 若来源链接失败，保留来源字段并提供复制链接/反馈入口。

内容以[骑行应急知识内容稿](./事故处理指南内容稿.md)为初稿。由于 2026 年 5 月公安部已就修改该规定公开征求意见，上线前必须再次确认是否已有正式新规；征求意见稿不得当作现行规则展示。

### 3.6 设置页完善

| 分组 | P0 能力 | 状态要求 |
|---|---|---|
| 账号与安全 | 登录状态、退出登录；注销入口先进入说明页（流程未就绪时明确标“暂不可申请”） | 高风险操作二次确认 |
| 隐私 | 个人资料公开范围、联系方式展示开关、隐私政策、个人信息清单 | 修改服务端生效并可回读 |
| 通知 | 同行/活动/系统通知偏好；微信系统通知权限入口 | 区分应用偏好与系统授权 |
| 系统权限 | 定位、相册/相机状态及“前往系统设置” | 不伪造授权状态 |
| 内容与帮助 | 意见反馈、安全须知、用户协议、隐私政策、事故指南 | 弱网可访问基础文本 |
| 存储与版本 | 清理非关键缓存、当前版本、构建类型（4/5 Tab） | 不清除登录态和待提交草稿 |
| 关于 | 品牌、客服/反馈渠道、开源许可（如适用） | 不展示虚假联系方式 |

## 4. 名称迁移规则

### 4.1 必须替换的用户界面文案

| 原名称 | 新名称 | 示例位置 |
|---|---|---|
| 约骑 | 同行助手 | Tab、页面标题、按钮、空状态、分享标题、消息分类、我的列表 |
| 发起约骑 | 发起同行 | 创建页标题和主按钮 |
| 报名约骑 | 加入同行 | 详情主操作和确认弹窗 |
| 法规检索/法规助手 | 骑行安全手册 | 首页入口、页面标题、关闭状态 |
| 消息 | 助手通知 | Tab、页面标题、列表标题、空状态 |
| 法规（作为产品栏目泛称） | 安全知识 | 搜索结果、分类入口、反馈说明 |

### 4.2 禁止误替换

- 官方文件标题、文号、发布机构、效力层级及原文引用；
- “遵守交通法律法规”等具有准确含义的安全表述；
- 管理后台用于内容治理的正式字段名称；
- 后端模型、表名、枚举、日志对象类型和 `/api/v1` 路径；
- 已发布通知历史正文，不做数据库全文替换。

## 5. 权限、状态与功能开关

| 能力 | 游客 | 登录用户 | 内容管理员 | 超级管理员 |
|---|---:|---:|---:|---:|
| 浏览路线/安全知识/事故指南 | 是 | 是 | 是 | 是 |
| 发起/报名同行或活动 | 否 | 是 | 是 | 是 |
| 提交/删除本人路线评论 | 否 | 是 | 是 | 是 |
| 审核/下架评论 | 否 | 否 | 是 | 是 |
| 发布事故指南版本、修改开关 | 否 | 否 | 否 | 是 |

新增服务端开关建议：

- `route.link_enabled`：路线与同行/活动绑定；
- `route.comment_enabled`：评论写入；
- `route.comment_read_enabled`：评论公开只读；
- `safety_guide.enabled`：骑行安全手册新增内容；
- `safety_agreement.enforced`：安全确认强制校验。

生产默认：评论写入和新指南内容在内容/法律评审前关闭；`safety_agreement.enforced` 只有在四条业务链路全部支持后才能开启，禁止出现只拦前端、不拦 API 的半上线状态。

## 6. 埋点

P0 事件包括：

- `route_create_companion_click`、`route_create_activity_click`；
- `route_bind_select`、`route_bind_remove`、`route_bind_submit_result`；
- `route_comment_submit`、`route_comment_moderation_result`、`route_comment_report`；
- `safety_guide_accident_open`、`safety_guide_source_click`、`safety_guide_feedback`；
- `safety_agreement_view`、`safety_agreement_confirm`、`safety_agreement_cancel`、`safety_agreement_submit_rejected`；
- `settings_item_open`、`settings_change_result`、`permission_settings_open`、`cache_clear_result`。

禁止在埋点或日志中记录评论全文、协议全文、手机号、openid、token、精确位置和事故个案描述。端到端验收必须验证服务端入库或分析平台收数，而非只检查客户端函数调用。

## 7. 验收标准

- 路线详情可分别发起同行和活动，服务端关系正确且下架路线不可新绑定；
- 原有不选路线的发布/报名链路保持兼容；
- 路线评论软删除和已屏蔽内容不能经公开列表、详情、缓存或搜索返回；
- 名称迁移扫描无用户侧遗漏，官方原文和技术契约未被误改；
- 四条高风险写链路均拒绝缺失、过期、伪造的协议版本，并保存可审计确认记录；
- 事故指南可在弱网下阅读，官方来源可见，版本过期时有提示；
- 设置项均有成功、失败、未登录、无权限和系统授权受限状态；
- 三端构建、后端测试、V1 回归、V2.1 纵向 E2E 和迁移演练通过；
- P0/P1 缺陷清零后才可进入灰度。
