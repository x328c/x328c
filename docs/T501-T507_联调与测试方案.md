# 疆行机车圈 V1.0 联调与测试方案（T501–T507）

**测试环境**：后端 `http://localhost:3000/api/v1`；小程序微信开发者工具；MySQL/Redis/COS 使用测试环境配置。  
**测试账号**：账号 A（普通发起人）、账号 B（普通报名人）、账号 M（内容审核员）、账号 S（超级管理员）。  
**前置条件**：已导入种子数据；后端、Redis、MySQL、管理后台均启动；小程序开发工具已关闭“合法域名校验”（仅本地联调）。

---

## 0. 测试准备与统一判定

### 0.1 接口响应判定

- HTTP 状态为 `2xx`，且业务响应 `code = 0`。
- 失败响应必须有可读 `message`，不得白屏、卡死或仅输出控制台异常。
- 受保护接口必须携带 `Authorization: Bearer <access_token>`。
- 列表均验证：首次加载、空列表、下拉刷新、分页（有下一页时）和重复进入。
- 涉及写操作时，操作后刷新相关详情/列表，验证数据库最终状态，而不只看 Toast。

### 0.2 账号与令牌准备

使用两个不同微信测试号登录小程序获得账号 A/B 的 Token；管理员从管理后台登录获得管理员 Token。若需命令行复现，可将 Token 填入：

```bash
export API=http://localhost:3000/api/v1
export TOKEN_A='Bearer <账号A access_token>'
export TOKEN_B='Bearer <账号B access_token>'
export ADMIN_TOKEN='Bearer <管理员 access_token>'
```

# T502 核心业务流程走查脚本

## 流程 1：约骑完整流程

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 1 | 账号 A 登录，进入个人中心补全昵称、车型、年限 | 资料保存成功，重新进入仍存在 |
| 2 | A 发起明天出发、最多 2 人的约骑 | 发布成功，约骑状态=报名中，A 进入详情 |
| 3 | 账号 B 登录，在广场找到该约骑 | 卡片显示 A 的头像、人数 `0/2` |
| 4 | B 进入详情，确认报名 | 成功 Toast；B 按钮为“已报名”；人数 `1/2` |
| 5 | A 打开消息中心 | 出现“有人报名”未读通知；未读数/角标+1 |
| 6 | 将出发时间调整到未来 2 小时内，执行/等待定时任务 | 状态变“即将出发”；已报名用户收到出发提醒通知 |
| 7 | 将出发时间调整到已开始，再执行定时任务 | 状态变“进行中” |
| 8 | 将出发时间调整到 8 小时前，再执行定时任务 | 状态变“已结束”，Redis Geo 中不再存在该约骑 |

## 流程 2：活动完整流程（需要审核）

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 1 | A 发布活动，开启“需要审核” | 创建成功，活动状态=报名中，`need_approval=true` |
| 2 | B 进入活动详情并报名 | 提示“已提交/审核中”，报名记录状态=1，活动通过人数不增加 |
| 3 | A 在活动报名管理中审核 B 并选择“通过” | 记录状态变2，活动 `register_count+1` |
| 4 | B 打开消息中心 | 收到“活动报名已通过”通知，详情展示“已报名” |
| 5 | 重复审核/重复报名 | 业务提示“已处理/已报名”，数据不重复增加 |

## 流程 3：管理后台治理流程

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 1 | 管理员 S 使用账号密码登录 | 获得独立管理员 Token，进入后台 |
| 2 | 查看约骑/活动列表，按状态、标题、发起人搜索 | 结果与种子数据一致，待复审标签正确 |
| 3 | 下架一条违规约骑/活动 | 状态更新为下架；小程序公开列表不再显示 |
| 4 | 在用户管理中封禁违规用户并填写原因 | `users.status=0`，该用户后续受保护接口被拒绝 |
| 5 | 解封该用户 | 状态恢复=1，可重新访问 |

# T504 异常场景与边界测试

| 分类 | 用例 | 步骤 | 预期结果 |
|---|---|---|---|
| 网络异常 | 断网发布 | 断网后提交约骑/活动 | 请求超时或网络提示；表单内容保留；不出现假成功 |
| 网络异常 | 断网报名 | 断网后确认报名 | 显示失败；按钮恢复可点击；刷新后人数未变化 |
| 重复提交 | 连续点击发布 | 快速点击提交按钮 3 次 | 前端 loading 防抖；后端至多创建 1 条 |
| 重复报名 | B 对同一约骑/活动重复报名 | 第二次调用报名接口 | 返回明确业务提示，人数不重复增加 |
| 重复取消 | 连续调用 leave | 第一次成功后再次调用 | 幂等成功或明确提示，人数不为负数 |
| 权限越界 | 非发起人编辑/取消/移除报名者 | B 调 A 创建的资源接口 | HTTP 403/业务无权限；数据不改变 |
| 权限越界 | 普通管理员调用超级管理员封禁 | 使用审核员 Token | 403，用户状态不变 |
| 数据边界 | 0 人、满员 | 创建后无人报名；报名至最大人数后继续报名 | 0 人展示正常；满员实时显示且拒绝后续报名 |
| 数据边界 | 文本长度 | 标题 0/30/31，说明 0/200/201，活动详情最大/超最大 | 前端提示，后端二次校验；特殊字符/XSS 不执行脚本 |
| 数据边界 | 坐标/人数 | 经纬度边界、最小人数>最大人数、人数0 | 均拒绝无效数据且 message 可读 |
| 时间边界 | 约骑取消报名 | 分别在出发前 2:00:01、2:00:00、1:59:59 操作 | 仅大于等于规则允许的时间段可取消；边界行为与产品规则一致 |
| 时间边界 | 活动取消报名 | 分别在开始前 24h±1 秒操作 | 仅开始前至少24小时允许取消 |
| 文件异常 | 非 jpg/png/webp、>5MB、伪造 callback | 上传或回调提交 | 后端拒绝；不写有效文件记录 |
| Token 异常 | Access Token 过期、Refresh Token 过期 | 请求受保护接口 | 前者刷新后重试；后者清会话并回到登录流程 |

# T505 简单压力测试

## 1. 安装与通用要求

```bash
npm i -g autocannon
export API=http://localhost:3000/api/v1
```

压测前记录机器配置、数据库连接数、Redis 内存；压测后检查错误率、MySQL 慢查询、Redis 慢日志和 CPU/内存。测试数据应至少覆盖分页与附近查询结果。

## 2. autocannon 命令

```bash
# 约骑列表：目标 TP99 ≤ 300ms
autocannon -c 100 -d 30 -m GET "$API/rides?page=1&pageSize=20&city_code=650100"

# 附近约骑：目标 TP99 ≤ 500ms
autocannon -c 100 -d 30 -m GET "$API/rides/nearby?city_code=650100&latitude=43.8&longitude=87.6&radius=10"

# 约骑详情：替换为存在的测试 ID，目标 TP99 ≤ 200ms
autocannon -c 100 -d 30 -m GET "$API/rides/<RIDE_ID>"
```

可选 `wrk` 命令：

```bash
wrk -t4 -c100 -d30s "$API/rides?page=1&pageSize=20&city_code=650100"
wrk -t4 -c100 -d30s "$API/rides/nearby?city_code=650100&latitude=43.8&longitude=87.6&radius=10"
wrk -t4 -c100 -d30s "$API/rides/<RIDE_ID>"
```

**通过标准**：无 5xx；网络/超时错误率 `< 1%`；TP99 分别不超过 300ms、500ms、200ms。未达标时记录 SQL、Redis 命令和接口 Trace ID，先定位 N+1 查询、缺失索引、缓存穿透或 Geo 查询数据量问题。
