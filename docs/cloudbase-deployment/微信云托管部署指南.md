# 疆行机车圈 NestJS 后端：微信云托管部署指南

> 本目录是部署交付物，不会修改 `backend/` 中的现有源代码。部署前，将本目录的 `Dockerfile`、`.dockerignore`、`docker-compose.prod.yml`、`.env.production.example` 复制到 `backend/` 根目录。

## 0. 部署前检查

1. 在 `backend/` 中复制环境变量模板：`cp .env.production.example .env.production`，填写真实值；严禁将 `.env.production` 上传到 Git 或代码包。
2. 生产数据库与 Redis 应使用云服务内网地址，不能填写 `localhost`。云托管容器无法连接你 Mac 上的 MySQL 或 Redis。
3. 在腾讯云部署 MySQL（例如 TencentDB for MySQL）和 Redis（例如 TencentDB for Redis），在相同地域/VPC 下为云托管开通网络访问，再填写它们的内网域名、端口、账号与密码。
3. 确认 `prisma/migrations/` 已包含全部迁移；镜像启动时会执行 `prisma migrate deploy`。
4. 腾讯云 COS、内容安全、微信 AppSecret 使用最小权限的正式密钥；不要复用开发环境泄露过的密钥。

## 1. 本地准备与打包

在 `backend/` 根目录中放入下列部署文件：

- `Dockerfile`
- `docker-entrypoint.sh`
- `.dockerignore`
- `docker-compose.prod.yml`（仅本地验证，可不上传）
- `.env.production.example`（示例，不含真实密钥）

代码包必须包含：

- `src/`
- `prisma/`（包含 `schema.prisma` 和 `migrations/`）
- `package.json`、`package-lock.json`
- `tsconfig.json`、`tsconfig.build.json`、`nest-cli.json`
- `Dockerfile`、`.dockerignore`

必须排除：`node_modules/`、`dist/`、`.env`、`.env.production`、`.git/`、`logs/`、`*.log`。

先做本地镜像验证：

```bash
cd ~/projects/jiangxing/backend
docker build -t jiangxing-backend .
```

本地三服务验证：

```bash
cp .env.production.example .env.production
# 编辑 .env.production，至少填入 JWT、微信、COS 等变量；Compose 会覆盖数据库和 Redis 地址。
docker compose -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml ps
curl http://localhost:3000/api/v1/health
docker compose -f docker-compose.prod.yml logs -f app
```

健康接口预期返回包含 `"status":"ok"` 的 JSON。结束本地测试：

```bash
docker compose -f docker-compose.prod.yml down
```

在 `backend/` 根目录打包。注意命令中的 `.` 表示压缩**目录内文件**，而不是最外层 `backend` 文件夹：

```bash
zip -r jiangxing-backend.zip . -x "node_modules/*" "dist/*" ".env" ".env.production" ".git/*" "logs/*" "*.log"
```

## 2. 上传到微信云托管

1. 登录微信云托管控制台，进入目标环境并创建服务。
2. 服务名使用小写字母、数字和连字符，例如 `jiangxing-backend`。
3. 部署方式选择“上传代码包 / 本地代码”，上传 `jiangxing-backend.zip`。
4. 目标目录保持代码包根目录；Dockerfile 名称填写 `Dockerfile`。
5. 监听端口填写 `3000`，按需要开启公网访问（小程序通过公网 API 访问时需要）。
6. 在环境变量区域逐项填写 `.env.production` 中的真实值；不要上传 `.env.production` 文件。
7. 发布新版本并将流量切换到新版本。

云托管要求 Dockerfile 位于代码包或目标目录根目录；上传 zip 时不能多嵌套一层顶级目录。服务仅配置一个监听端口，环境变量由控制台注入容器。[云托管服务设置](https://cloud.tencent.com/document/product/1243/77197/)

## 3. 构建与部署后验证

1. 等待控制台显示构建成功、实例就绪、流量已切换。
2. 查看运行日志，确认出现 NestJS 启动日志，且没有 Prisma migrate 或 Redis 连接错误。
3. 使用服务默认公网域名或绑定的 HTTPS 域名访问：

```text
https://<你的云托管域名>/api/v1/health
```

预期：HTTP 200，响应包含 `status: ok`、时间戳和 `service: jiangxing-backend`。

4. 在微信公众平台把该 HTTPS 域名配置为小程序 request 合法域名；随后把前端 API 基址替换为该 HTTPS 地址，再进行真机验证。

云托管支持从本地代码/zip 构建镜像，运行端口、Dockerfile 和环境变量在版本配置中设置。[云托管版本配置说明](https://cloud.tencent.com/document/product/1243/49177/)

## 4. 常见问题

- **健康检查连接失败**：检查云托管监听端口是否为 3000，以及日志中 NestJS 是否已启动。当前健康路径是 `/api/v1/health`，不是 `/api/health`。
- **Prisma migrate deploy 失败**：检查 `prisma/migrations/` 是否打进代码包、`DATABASE_URL` 是否为云数据库内网地址、数据库账号是否有 DDL 权限。
- **Back-off restarting failed container，且启动日志止于 Prisma schema loaded**：这意味着容器还没有启动 NestJS，优先检查云托管环境变量中的 `DATABASE_URL`。重新上传本次修复后的包后，启动日志会明确显示迁移开始与实际 Prisma 错误。若仅为排障可暂时设 `RUN_PRISMA_MIGRATIONS=false` 验证应用和 Redis 是否能启动；确认后恢复为 `true` 完成迁移。
- **Redis 连接失败**：当前代码不读取 `REDIS_URL`，必须配置 `REDIS_HOST`、`REDIS_PORT`、`REDIS_PASSWORD`、`REDIS_DB`。
- **Dockerfile 找不到**：不要压缩最外层 backend 文件夹；应在 backend 目录内执行 zip 命令。
- **云上连接 localhost 失败**：容器内 `localhost` 只指向自身，数据库/Redis 必须使用云服务内网地址。腾讯云文档也说明本地可用的 localhost 配置在云托管中不可用。[云托管常见问题](https://cloud.tencent.com/document/product/1243/59521)
