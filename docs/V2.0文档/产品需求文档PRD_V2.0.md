# 摩搭子助手 — 产品需求文档 PRD V2.0

> 文档版本：V2.0（优化版）  
> 更新日期：2026-07-31  
> 依赖文档：[MRD](./市场需求文档MRD_V2.0.md) / [技术方案](./技术方案设计V2.0.md) / [项目计划](./项目计划表V2.0.md)

## 1. 版本目标

V2.0 在保持 V1.0 登录、约骑、活动、消息和后台能力稳定的前提下，交付“路线精选、法规检索、受控论坛”三个 MVP，验证内容对真实骑行连接的促进作用。

### 1.1 成功标准

- 三个新模块可独立灰度和关闭，不影响 V1.0 核心流程；
- 关键指标达到 MRD 的实验门槛；
- P0 场景具备正常、空、加载、错误、无权限和内容失效状态；
- 所有公开 UGC 均完成文字/图片审核或人工审核；
- 法规条目均有可访问来源、有效状态和最后复核时间；
- 发布门禁、回滚方案和运营 SOP 通过演练。

### 1.2 优先级定义

| 优先级 | 定义 | 发布规则 |
|---|---|---|
| P0 | 构成 MVP 闭环或合规/安全必需 | 未完成不得开放对应模块 |
| P1 | 明显改善体验但可延期 | 仅在不挤压 P0 测试时交付 |
| P2 | 探索性或高复杂度 | 进入 V2.1，不计入 V2.0 承诺 |

## 2. 范围

### 2.1 V2.0 范围

| 模块 | P0 | P1 |
|---|---|---|
| 路线 | 精选列表/筛选、详情、收藏、关联约骑、后台 CRUD/上下架 | 分享卡片、浏览历史 |
| 法规 | 分类/城市/关键词检索、详情与来源、纠错反馈、后台 CRUD/CSV 导入、复核任务 | 收藏、热门搜索 |
| 论坛 | 板块/列表/发帖/一级回复、点赞、举报、删除本人内容、后台审核/下架/禁言 | 收藏、搜索、精华/置顶 |
| 基础能力 | 品牌升级、埋点、限流、审计日志、功能开关、自动化测试基线 | 游标分页改造、图片 CDN 优化 |

### 2.2 明确不做

- 用户提交路线、GPX/KML、路线评分、真实轨迹导航、按路线几何距离搜索；
- 楼中楼、关注关系、@ 提及、私聊、二手交易、用户等级；
- AI 法律问答、法规自动采集、向量检索；
- 公众号模板消息、全量深色模式、原生 App/H5。

## 3. 用户与权限

| 角色 | 浏览公开内容 | 收藏/点赞 | 发帖/回复 | 内容管理 | 法规发布 |
|---|---|---|---|---|---|
| 游客 | 是 | 否 | 否 | 否 | 否 |
| 正常用户 | 是 | 是 | 是 | 仅本人内容 | 否 |
| 禁言用户 | 是 | 是 | 否 | 可删除本人内容 | 否 |
| 内容审核员 | 是 | — | — | 审核、下架、处理举报 | 草稿/编辑 |
| 超级管理员 | 是 | — | — | 全部 | 发布/下架 |

被封禁用户按 V1.0 规则处理。所有管理操作必须记录操作人、对象、前后状态、原因和时间。

## 4. 信息架构

底部 5 个 Tab：**约骑、路线、论坛、消息、我的**。活动仍从约骑页顶部分类进入，法规从首页快捷入口和“我的”进入，不占用 Tab。

旧版本用户升级后默认进入“约骑”，其浏览和发布路径不增加步骤。论坛未通过资质核验时，提审构建使用 4 Tab 配置；已发布版本中若论坛临时关闭，服务端拒绝写入并展示维护页，下一次提审切回 4 Tab。

## 5. 路线精选 MVP

### 5.1 用户故事

| ID | 需求 | 优先级 |
|---|---|---|
| RT-01 | 按城市、类型和难度浏览已发布路线 | P0 |
| RT-02 | 查看路线的里程、时长、点位、路况和安全提示 | P0 |
| RT-03 | 收藏/取消收藏路线 | P0 |
| RT-04 | 从路线进入相关约骑 | P0 |
| RT-05 | 管理员创建、编辑、预览、发布和下架路线 | P0 |
| RT-06 | 分享路线小程序卡片 | P1 |

### 5.2 列表与详情

- 列表默认按运营推荐权重、更新时间和 ID 稳定排序；支持城市、类型、难度筛选；
- “附近”在 V2.0 仅表示路线起点所在城市，不宣称按完整轨迹测距；
- 卡片展示封面、名称、城市、里程、预计时长、难度和收藏状态；
- 详情展示地图折线、起终点/途经点、路况、适合车型、最佳季节、风险提示、信息更新时间；
- 地图异常时降级为点位列表，不阻断正文浏览；
- 关联约骑按城市或显式关联返回，最多展示 3 条有效约骑。

### 5.3 收藏

- 未登录点击收藏，保存返回地址并引导登录；登录成功后返回原页，由用户再次确认收藏；
- 收藏和取消收藏必须幂等；重复请求不重复计数；
- 路线下架后不出现在公开列表，已收藏用户看到“内容已下架”状态。

### 5.4 后台与验收

- 路线状态：草稿 → 已发布 → 已下架；只有超级管理员可发布；
- 发布前校验封面、城市、起终点、里程、时长、难度、安全提示和维护人；
- 编辑已发布路线产生审计记录；重大安全信息变更需要重新发布；
- 验收：筛选准确、地图降级可用、收藏幂等、下架即时生效、关联约骑仅返回可见内容。

## 6. 法规检索 MVP

### 6.1 产品边界

法规助手提供官方信息的结构化索引和原文入口，不生成个案判断，不承诺替代执法机关或专业法律意见。

### 6.2 用户故事

| ID | 需求 | 优先级 |
|---|---|---|
| RG-01 | 按分类、地区浏览有效条目 | P0 |
| RG-02 | 按标题、文号和标签搜索 | P0 |
| RG-03 | 查看来源、适用地区、生效/失效日期和最后复核时间 | P0 |
| RG-04 | 提交“内容错误/已过期/链接失效”反馈 | P0 |
| RG-05 | 管理员录入、复核、发布、下架、修订和 CSV 导入 | P0 |
| RG-06 | 收藏条目 | P1 |

### 6.3 检索与详情

- 默认仅展示“现行有效”条目；用户可切换查看“已失效/已替代”；
- 搜索范围为标题、文号、发布机构和标签，结果按匹配度、效力层级和更新时间排序；
- 无结果时提供分类入口和纠错反馈，不自动生成答案；
- 详情必须展示：标题、文号、发布机构、效力层级、适用地区、发布日期、生效日期、状态、摘要、原文链接、最后复核时间和复核人；
- 超过复核周期或来源链接不可访问时显示醒目提示，并从推荐位移除。

### 6.4 内容工作流

状态：草稿 → 待复核 → 已发布 → 已失效/已下架。录入人与复核人不能是同一人；修订保留历史版本和更正说明。

CSV 导入流程：上传 → 字段/重复校验 → 预览 → 导入草稿。批量导入不得直接发布。

验收：所有已发布条目必填来源字段；失效条目默认不可见；修订可追溯；纠错反馈 24 小时内进入处理队列。

## 7. 论坛受控 MVP

### 7.1 用户故事

| ID | 需求 | 优先级 |
|---|---|---|
| FM-01 | 浏览板块、帖子和一级回复 | P0 |
| FM-02 | 发布文字和图片帖子 | P0 |
| FM-03 | 回复、点赞和取消点赞 | P0 |
| FM-04 | 删除本人帖子/回复 | P0 |
| FM-05 | 举报帖子/回复/用户 | P0 |
| FM-06 | 审核员审核、下架、处理举报和禁言 | P0 |
| FM-07 | 搜索、收藏、置顶和加精 | P1 |

### 7.2 板块与发布

首批板块：新手入门、骑行装备、维修保养、摩旅日记。不开放二手交易和纯灌水板块。

- 标题 5-50 字；正文 10-3000 字；图片 0-9 张；V2.0 使用受限格式，不接受任意 HTML；
- 提交后进入“审核中”；文字和图片均通过审核才公开；审核服务不可用时保持待审核，不直接放行；
- 频率默认：发帖 1 次/分钟、5 次/天；回复 1 次/10 秒、50 次/天，可远程配置；
- 用户能看到审核状态和驳回原因；驳回后可修改重提；
- 删除采用软删除，公开内容隐藏，审计与举报证据按数据保留策略保存。

### 7.3 回复与排序

- V2.0 只做一级回复，按时间正序游标分页；
- 帖子列表支持“最新”和“热门”，热门分数由服务端计算并设置上限与时间衰减；
- 置顶帖单独排序，不参与普通热度竞争；浏览计数异步聚合，不能影响详情响应。

### 7.4 治理与验收

- 前台提供举报入口，原因枚举与补充说明沿用 V1 举报体系；
- 后台队列区分待审内容、用户举报和自动审核异常；
- 禁言支持截止时间、原因和解除；用户提交时必须得到明确提示；
- 验收：未审核内容不可从公开接口获取；重复点赞幂等；越权编辑/删除被拒绝；禁言即时生效；所有处置有审计记录。

## 8. V1.0 基础改造

### 8.1 P0

- 品牌名称和主色统一，保留旧名称迁移说明；
- 后端接入结构化日志、请求 ID、Swagger/OpenAPI 和统一错误码；
- 建立后端核心 Service 单测、API 集成测试和三条端到端冒烟流程；
- 建立功能开关与灰度配置；
- 管理后台操作日志；
- 关键写接口限流、权限校验和幂等保护。

### 8.2 P1

- 高频列表游标分页、图片缩略图/CDN、统一骨架屏和错误状态；
- 小程序分包；主包体积在 CI 中监测并设置预算；
- 约骑/活动分享卡片优化。

## 9. 非功能需求

| 类别 | 要求 | 验证方式 |
|---|---|---|
| 可用性 | 核心 API 月可用率 ≥99.9%（不含计划维护） | 服务端监控 |
| 性能 | 列表/详情 API P95 ≤300ms，P99 ≤800ms；不含第三方审核请求 | 压测与生产监控 |
| 前端 | 4G/中端机下列表可交互 P75 ≤2s | 真机采样 |
| 安全 | 鉴权、越权、XSS、上传类型/大小、限流测试通过 | 安全检查表 |
| 隐私 | 最小化采集；位置、联系方式等敏感信息遵循现有授权策略 | 隐私清单评审 |
| 可恢复 | 迁移前备份；RPO ≤24h，RTO ≤4h；完成恢复演练 | 演练记录 |
| 可观测 | 请求 ID、错误率、延迟、审核积压、任务失败均有看板/告警 | 发布门禁 |

性能目标以部署环境压测基线为准，不再使用无法验证的“所有接口 TP99 <200ms”作为统一承诺。

## 10. 埋点与实验

P0 事件：模块曝光、列表加载结果、筛选、详情查看、收藏、关联约骑点击、法规搜索与结果点击、发帖/回复提交与审核结果、举报、后台处置。

所有事件必须有事件字典，明确触发时机、属性、去重规则和数据负责人。上线前使用测试账号验证端到端入库，不只验证客户端是否调用。

## 11. 发布门禁

每个模块全量前必须同时满足：

- P0 验收用例 100% 通过，P1 不阻断；
- 无 P0/P1 未解决缺陷；
- 迁移、回滚、功能开关和数据恢复已演练；
- 内容审核、举报处置和法规复核 SOP 已安排负责人；
- 10% 与 30% 灰度阶段守护指标均达标；
- 小程序类目、隐私声明和内容资质复核完成。

## 12. 待决策项

| 决策 | 截止点 | 默认方案 |
|---|---|---|
| 论坛类目与资质是否满足 | 第 2 周 | 不满足则隐藏论坛入口 |
| 首批路线覆盖城市 | 第 2 周 | 选 V1.0 活跃度最高的 3 个城市 |
| 法规复核周期 | 第 2 周 | 全国 90 天、地方 30 天 |
| 16 周人员是否到位 | 项目启动 | 不足则论坛顺延至 V2.1 |
