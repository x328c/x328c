# S5 回滚手册

## 触发条件

P0（数据损坏、权限/合规泄露、V1 核心链路不可用）立即停止发布并回滚；P1（大面积列表、登录、报名、审核治理不可用）清零后才允许扩大灰度。

## 操作顺序

1. 保留告警、request ID、任务失败记录和数据库快照。
2. 由超级管理员在后台“功能开关”页面先关闭论坛写入，再关闭论坛及受影响的路线/法规开关，填写事件编号或回滚原因；论坛关闭后公开查询不得返回缓存正文。
3. 回滚应用版本，或前滚兼容修复；不要回滚/删除已执行迁移。
4. 若必须恢复数据库，使用迁移前备份执行恢复演练流程，校验 V1 用户、约骑、报名和通知数据。
5. 运行三条 V2 E2E 和 V1 冒烟，确认错误响应仍包含 requestId，确认审计和任务失败记录可查。
6. 记录恢复时间、RPO/RTO、未解决缺陷和再次开启开关的审批人。

若管理后台不可用，可由受权运维人员按应急流程直接修改 `feature_flags`，随后删除 `v2:feature-flag:*` 对应缓存 Key，并补录事件和审计说明；该路径仅用于管理面故障，不作为日常操作方式。
