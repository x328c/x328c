# 摩搭子助手 — 项目计划 V2.0

> 文档版本：V2.0（优化版）  
> 更新日期：2026-07-31  
> 计划周期：16 周  
> 计划原则：范围可裁剪，质量门禁不可裁剪

## 1. 资源与排期前提

16 周计划成立的最低资源：

| 角色 | 投入 | 关键责任 |
|---|---:|---|
| 产品负责人 | 40% | 范围、指标、验收、跨角色决策 |
| UI/UX | 前 4 周 80%，之后 20% | Token、原型、状态矩阵、设计走查 |
| 后端 | 1 人全职 | API、数据、审核、迁移、可观测 |
| 小程序前端 | 1 人全职 | 页面、状态、分包、埋点、真机验证 |
| 管理后台前端 | 0.5 人 | 路线/法规/审核/审计后台 |
| 测试 | 前 8 周 30%，后 8 周 70% | 测试设计、自动化、回归、灰度验证 |
| 内容/运营 | 0.5 人 | 路线与法规供给、论坛审核、SOP |

若管理后台与小程序由同一名前端兼任，或没有独立内容负责人，16 周内默认顺延论坛，不通过压缩测试补偿。

## 3. 阶段计划

### W1-W2：发现、基线与立项门禁

| 工作包 | 负责人 | 交付/验收 |
|---|---|---|
| V1 数据与质量基线 | 产品+技术+测试 | 14 天漏斗、留存、错误率；三条核心冒烟流程 |
| 用户研究/竞品走查 | 产品+设计 | 12 次访谈、首轮可用性结论 |
| 范围与指标冻结 | 产品 | P0/P1/P2、事件字典、守护指标签字 |
| 论坛类目与资质核验 | 产品+运营 | 书面结论；不满足则论坛关闭 |
| 法规治理方案 | 内容+产品 | 来源标准、双人复核、复核周期、纠错 SLA |
| 技术 Spike | 技术 | 中文搜索、地图折线、文字/图片审核、迁移 POC |
| UI 原型与状态矩阵 | 设计 | 三模块 P0 流程和异常状态评审通过 |

M0 决策：资源或前置条件不满足时，按“论坛 → 路线 P1 → 法规 P1”顺序裁剪。

## 5. Definition of Ready / Done

### 开发就绪（Ready）

- 需求 ID、优先级、原型、正常/异常流程已明确；
- API/数据/埋点契约已评审；
- 依赖、权限、内容安全与回滚方式明确；
- 验收用例可执行，无“待完善”等占位描述。

### 完成（Done）

- 代码评审通过，无未解释的高风险变更；
- 单元/集成/E2E 中适用项通过，CI 全绿；
- 加载、空、错误、无权限和内容失效状态完成；
- 日志、指标、告警、埋点和审计已验证；
- 文档/OpenAPI/运营 SOP 同步；
- 测试环境验证并由产品/设计/测试完成验收。

仅“代码写完”或“页面可打开”不算完成。

## 6. 缺陷与发布规则

| 等级 | 定义 | 发布规则 |
|---|---|---|
| P0 | 数据损坏、安全/合规、核心流程不可用 | 立即停止发布/回滚 |
| P1 | 主要功能不可用或大面积错误 | 清零后才能扩大灰度 |
| P2 | 有绕行方案的局部问题 | 记录负责人和修复版本 |
| P3 | 文案/轻微视觉问题 | 不阻断，但不得长期无归属 |

## 7. 风险登记

| 风险 | 触发条件 | 应对 | Owner |
|---|---|---|---|
| 后端/小程序容量接近上限 | 连续两周 >计划 20% | 先砍 P1，再顺延论坛 | 项目负责人 |
| 论坛资质不满足 | M0 无书面结论 | 构建 4 Tab 版本，论坛不开启 | 产品 |
| 法规内容延误 | W8 未完成 30 条复核 | 缩小地区/分类，不降低来源标准 | 内容负责人 |
| 审核服务不稳定 | 超时率 >5% 或积压 >2 天能力 | 保持待审、限流、人工兜底、关闭发帖 | 技术+运营 |
| V1 核心指标下降 | 发布/报名成功率下降 >2pp | 停止扩大灰度，回滚导航/入口 | 产品+技术 |
| 迁移风险 | 演练超时或数据校验失败 | 不执行生产迁移，修正后重演练 | 后端 |

## 8. 变更控制

- M0 后新增需求必须说明要替换的同等工作量范围；
- M5 后只接受 P0/P1 缺陷修复；
- 任何涉及账号、位置、联系方式、UGC、法规准确性或支付的变更必须重新做安全/合规评审；
- 周报只报告里程碑证据、剩余风险和指标，不用“完成百分比”替代可验收成果。
