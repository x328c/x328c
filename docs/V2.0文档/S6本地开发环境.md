# 本地开发环境（V2.0）

本文件只描述收敛后的本地 Docker 开发环境。它不替代测试环境，也不允许导入生产真实数据。

## 启动本地依赖

仓库根目录执行：

```bash
docker compose up -d
```

项目只保留根目录 `docker-compose.yml`：

| 服务 | 地址 | 本地凭据 |
| --- | --- | --- |
| MySQL 8 | `127.0.0.1:3306` | 数据库 `jiangxing_db`，凭据以本地 Compose 为准 |
| Redis 7 | `127.0.0.1:6379` | 本地开发实例 |

## 应用迁移与 fixture

不修改 `.env`，在启动后端的 shell 中临时设置连接信息：

```bash
cd backend
export DATABASE_URL='mysql://root:本地密码@127.0.0.1:3306/jiangxing_db'
export REDIS_HOST=127.0.0.1
export REDIS_PORT=6379
npx prisma migrate deploy
MODAZI_DEV_SEED_CONFIRM=1 npm run db:seed:dev
```

`migrate deploy` 会按顺序应用 V1 历史迁移和 V2 增量迁移；不要用 `prisma db push` 替代它。seed 只写入带有开发标识的虚构账号、路线、法规和论坛 fixture，并且可重复执行。默认功能开关仍为：路线、法规、论坛关闭，论坛发布模式为 `invite_only`。

开发管理员账号为 `dev-owner` 和 `dev-reviewer`，默认密码为 `dev-only-password-change-me`；仅限本地 fixture，首次使用后可在本地自行更换。也可以通过 `MODAZI_DEV_ADMIN_PASSWORD` 临时指定密码。脚本要求 `MODAZI_DEV_SEED_CONFIRM=1`，且拒绝 `NODE_ENV=production`。

## 本地完整 V2.0 联调

代码和空库默认值始终安全关闭。需要验证完整 V2.0 时，使用超级管理员登录管理后台，在“功能开关”页面填写原因并开启：

| 开关 | 本地完整联调值 |
| --- | --- |
| `route.enabled` | `true` |
| `regulation.enabled` | `true` |
| `forum.enabled` | `true` |
| `forum.write_enabled` | `true` |
| `forum.publish_mode` | `all` |

后台会批量写入 `feature_flags`、追加管理员审计日志并失效 Redis 缓存。论坛总开关关闭时不能开启写入；关闭论坛总开关时，管理页面会同步关闭论坛写入。审核服务超时或异常仍必须保持内容 `PENDING`。

小程序论坛 Tab 是构建时能力，完整联调使用：

```bash
cd frontend
npm run build:weapp:test:5tab
```

4 Tab 和生产构建不会因为服务端开关而运行时增加论坛 Tab。本地联调结束后可在后台恢复安全配置：论坛写入、论坛、法规和路线均关闭，发布模式恢复 `invite_only`。

## 与测试环境的边界

- 数据库型 E2E 在现有 MySQL 内创建名称以 `_test` 结尾的临时数据库，测试结束后精确删除；禁止连接 `jiangxing_db`，也不为测试另建 Docker 环境。
- 旧隔离环境只同步可重复生成的虚构 fixture；不复制 token、手机号、精确位置、真实法规/帖子全文或外部密钥。
- 应用缓存键使用现有版本前缀；测试不得清空本地开发 Redis 的无关键。
- `docker compose ... down` 默认不会删除卷；只有确认要清空本地数据时才显式执行 `down -v`。

## 停止服务

```bash
docker compose stop
```
