# 摩搭子助手 — UI/UX 设计规范 V2.0

> 文档版本：V2.0（优化版）  
> 更新日期：2026-07-31  
> 目标平台：微信小程序（主）/ Web 管理后台（辅）

## 1. 体验目标

V2.0 的设计重点是让新增内容能力自然服务于“找到合适的骑行连接”，而不是让用户在三个新频道之间迷路。

核心原则：

- **主链路稳定**：升级后仍默认进入约骑，发布/报名步骤不增加；
- **可信可解释**：路线显示更新时间与风险提示，法规显示来源与有效状态，论坛显示审核状态；
- **状态完整**：页面设计必须覆盖加载、空、失败、无权限、审核中、已下架；
- **移动优先**：优先单手操作、弱网和中端 Android 真机体验；
- **少而一致**：优先复用 V1 卡片、状态、弹窗和骨架屏，不为每个模块另造交互。

## 2. 信息架构与导航

正式方案为 5 个 Tab：**约骑、路线、论坛、消息、我的**。活动保留在约骑页内，法规通过首页快捷入口和“我的”进入。

若论坛类目/资质未满足，发布构建使用 4 Tab 版本：**约骑、路线、消息、我的**。原生 TabBar 列表不依赖运行时动态删除；服务端功能开关仍负责拒绝已关闭模块的访问。

导航规则：

- 每个 Tab 保持独立导航栈；再次点击当前 Tab 回到根页并滚动到顶部；
- 从路线进入关联约骑时保留路线返回上下文；
- 登录拦截后返回原任务页，不丢失用户的筛选条件；
- 分享进入已下架内容时展示统一失效页并提供可行动入口。

## 3. 设计令牌

### 3.1 色彩

| Token | 色值 | 用途 |
|---|---|---|
| `brand-orange` | `#FF6A00` | 品牌标识、图标、选中态、大面积非文字强调 |
| `action-orange` | `#C74700` | 白字主按钮，满足普通文字对比度要求 |
| `ink-900` | `#1F1F1F` | 主文字、深色导航 |
| `ink-600` | `#595959` | 次要文字 |
| `ink-400` | `#767676` | 辅助文字；避免更浅灰用于正文 |
| `surface` | `#FFFFFF` | 卡片/输入背景 |
| `canvas` | `#F5F5F5` | 页面背景 |
| `border` | `#E5E5E5` | 分割与边框 |
| `success` | `#237804` | 成功/通过 |
| `warning` | `#AD6800` | 待审核/提醒 |
| `danger` | `#C62828` | 错误/删除/失效 |
| `link` | `#0958D9` | 文本链接 |

`#FF6A00` 上不使用小号白字。实心主按钮使用 `action-orange + #FFFFFF`，品牌橙背景若承载文字则使用 `ink-900`。信息不能只靠颜色表达，必须配合图标或文字。

### 3.2 字体与间距

以 375px 设计稿为基准，开发使用 rpx/响应式换算。

| 角色 | 设计尺寸 | 行高 | 用途 |
|---|---:|---:|---|
| Page title | 20px / 600 | 28px | 页面标题 |
| Section title | 18px / 600 | 26px | 区块标题 |
| Item title | 16px / 600 | 24px | 卡片/列表标题 |
| Body | 14px / 400 | 22px | 正文 |
| Caption | 12px / 400 | 18px | 时间、辅助字段 |

不使用 10px 承载必须阅读的信息。间距采用 4px 基础网格，常用 8/12/16/24/32px；页面水平边距 16px，卡片内边距 16px，列表项最小垂直间距 12px。

### 3.3 圆角、阴影与触控

- 卡片 12px，输入/按钮 8px，底部面板顶部 16px；
- 主要依赖边框和层级，不用重阴影堆叠；卡片阴影最多 `0 2px 8px rgba(0,0,0,.06)`；
- 可点击区域至少 44×44 逻辑像素；图标视觉尺寸可小于点击区域；
- 危险操作使用文字按钮或次级位置，不与主操作并排等权。

## 4. 通用组件与状态

### 4.1 组件清单

| 组件 | 说明 |
|---|---|
| `StatePanel` | 统一空、错误、无权限、下架、审核中状态 |
| `FilterBar` / `FilterSheet` | 列表筛选与已选条件回显 |
| `StatusTag` | 状态文字 + 图标 + 颜色 |
| `SourceBlock` | 法规来源、有效状态和复核时间 |
| `ModerationBanner` | 审核中/驳回原因/禁言提示 |
| `StickyActionBar` | 收藏、发布、回复等底部操作；适配安全区 |
| `Skeleton` | 与真实布局等高，避免加载后跳动 |
| `ConfirmDialog` | 仅用于不可逆或高风险操作 |

### 4.2 必交状态矩阵

| 状态 | 展示 | 允许操作 |
|---|---|---|
| 首次加载 | 结构化骨架屏 | 返回 |
| 分页加载 | 列表底部加载行 | 保留已加载内容 |
| 空结果 | 原因 + 建议 + 清除筛选 | 清除筛选/返回 |
| 网络失败 | 保留上下文 + 重试 | 重试 |
| 未登录 | 说明登录价值 | 登录/取消 |
| 审核中 | 状态、预计处理说明 | 查看/撤回或编辑（按规则） |
| 审核驳回 | 原因和修改建议 | 修改重提 |
| 内容下架/失效 | 失效原因的安全摘要 | 返回列表/反馈 |
| 功能关闭 | 维护说明 | 返回约骑 |

## 5. 路线体验

### 5.1 列表

页面结构：标题 → 城市/类型/难度筛选 → 路线列表。卡片信息顺序：封面、路线名、城市/类型/难度、里程/时长、更新时间。首屏不展示浏览/收藏等低价值计数堆叠。

交互要求：

- 筛选结果即时回显，支持一键清除；
- “附近”文案改为“本城路线”，避免误导为轨迹距离；
- 滚动和切页后返回保留位置；
- 封面加载失败使用固定比例占位，不引起卡片跳动。

### 5.2 详情

信息顺序：地图/点位 → 核心参数 → 安全提示 → 路线分段 → 关联约骑 → 信息维护说明。

- 地图不作为唯一载体，必须有文字点位列表；
- 风险提示用高对比提醒块，不与商业推荐混放；
- 底部主操作为“查看相关约骑”，收藏为图标+文字次操作；
- 数据更新时间超过阈值时显示“信息可能已变化”。

## 6. 法规体验

### 6.1 首页与搜索

入口突出“城市政策、驾驶证、车辆管理、交通规则”四类任务，不用六宫格塞满所有分类。搜索支持标题/文号/机构，输入前展示高频任务，输入后显示命中字段。

无结果时不生成答案，提供：换关键词、浏览分类、提交需求。

### 6.2 详情

首屏必须看到：有效状态、适用地区、生效日期、最后复核时间。正文前展示 `SourceBlock`，原文链接使用明确文案“查看官方原文”。

已失效条目使用灰色状态条并推荐替代文件；来源不可访问或逾期未复核使用黄色提醒；“纠错”入口常驻正文末尾。

## 7. 论坛体验

### 7.1 浏览与发布

- 首页直接展示 4 个板块和最新帖子，不使用无数据支撑的“热门轮播”；
- 列表卡片展示标题、作者、发布时间、板块、回复/点赞；置顶/精华 P1 再启用；
- 发帖采用标题、正文、图片三段式，不引入复杂富文本工具栏；
- 提交前提示内容规范，提交后进入清晰的审核状态页；
- 审核失败展示可执行的修改建议，不只显示“违规”。

### 7.2 详情与回复

正文、图片、互动栏、一级回复按自然阅读顺序排列。底部回复输入框仅登录且未禁言用户可用；禁言状态展示截止时间和原因。

举报放在更多菜单内，但最多两步可达。删除本人内容必须确认；点赞不弹 Toast，以图标状态变化即时反馈。

## 8. V1.0 视觉迁移

- 先替换全局 Token，再逐页处理局部硬编码颜色；
- 旧绿色状态色不机械替换为橙色，成功/警告/错误仍使用语义色；
- 品牌名称、导航标题、分享卡片、空状态和后台名称同步更新；
- Tab 由 3 项升级为 4/5 项后必须真机验证文字截断、角标、安全区和不同系统字体；
- 不在 V2.0 同时实施完整深色模式，避免使页面状态组合翻倍。

## 9. 管理后台

后台以效率和可追溯为主，不照搬小程序装饰风格。

- 列表筛选条件写入 URL，刷新后可恢复；
- 审核页采用内容预览 + 来源/风险 + 决策区布局；
- 批量导入必须有字段校验、错误行下载和确认步骤；
- 发布、下架、驳回、禁言均要求填写原因；
- 颜色只辅助状态，表格必须有文字状态；
- 高风险操作完成后显示操作日志 ID，便于追踪。

## 10. 动效、适配与无障碍

- 动效 120-240ms，尊重系统减少动态效果设置；不使用粒子效果作为 P0；
- 底部固定栏适配 `safe-area-inset-bottom`，地图和长列表在中端 Android 真机验证；
- 图片提供可理解的替代说明；表单字段有可见标签、错误信息和焦点定位；
- 文字可缩放时不截断关键操作；横向滑动不是发现核心功能的唯一方式；
- 发布前完成至少两轮 5-8 人可用性测试，关键任务完成率目标 ≥90%。

## 11. 设计交付与验收

设计交付不以“约 25 页”计完成，而按状态和流程验收：

- Figma 变量/Token、组件及变体；
- 路线、法规、论坛 P0 流程原型；
- 每个 P0 页面状态矩阵；
- 4/5 Tab 构建方案和图标资源（本地 PNG 普通/选中态）；
- 管理后台审核/发布/下架/批量导入流程；
- 真机走查记录、可用性测试问题与修订记录。

所有开发页面在合并前进行设计走查；存在文字截断、不可达状态、对比度或点击区域问题时不得标记完成。
