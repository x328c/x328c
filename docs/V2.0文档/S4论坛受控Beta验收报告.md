# S4 论坛受控 Beta 验收报告

日期：2026-08-01

## 范围结论

本阶段实现四个固定板块、文字和站内图片帖子、一级回复、点赞、举报，以及后台审核、
下架、禁言和板块治理。未实现楼中楼、关注、@、私聊、二手交易、复杂富文本、论坛搜索
或外链图片。

`forum.enabled` 与 `forum.write_enabled` 均安全默认关闭；`forum.publish_mode` 默认
`invite_only`。资质或审核服务不可用时，应用可以保持四 Tab，论坛内容不会自动放行。

## 数据与公开可见性

- 业务状态和审核状态分别存储；公开列表、详情和回复同时检查板块启用、业务发布、审核
  通过、发布时间及未软删除。
- 帖子先持久化为 `PENDING`，再审文字和全部图片；只有全部通过才进入 `PUBLISHED`。
- 明确违规进入 `REJECTED`；关闭、超时或异常保持 `PENDING` 并进入异常人工队列。
- 帖子最多 9 张图；图片必须来自当前用户的论坛上传记录，且通过服务端 MIME、扩展名、
  文件头和尺寸校验，不接受客户端外链。
- 回复模型没有 `parentId`；点赞使用 `(userId, targetType, targetId)` 唯一约束；计数由
  服务端事务派生。
- 禁言保存开始、结束、原因和创建管理员；到期禁言不会继续阻止发布。

## 审核、安全和权限

- 审核任务条件认领，版本化避免旧结果覆盖新编辑；最多 3 次，按 60/300/1800 秒退避，
  失败计数并保留人工重试、人工通过和驳回入口。
- 管理员人工通过、驳回、下架、禁言、解禁和板块状态变更均强制原因并追加
  `operation_logs`，保存管理员、动作、对象、原因、request ID 和时间。
- 发帖/回复检查登录、用户有效状态、灰度邀请、禁言、板块状态、长度、图片和服务端限流；
  持久化幂等键防止重复提交。
- 用户只能编辑本人待审或驳回内容，只能删除本人内容；管理员治理使用独立角色接口。
- 正文仅存纯文本；服务端拒绝脚本、事件属性、iframe、危险协议和编码后的脚本载荷。
- 举报扩展 V1 `report`，验证对象公开存在且禁止自我举报；证据保存对象状态和内容摘要
  哈希，不把帖子/回复全文复制到日志或审计。
- 论坛公开响应不使用正文列表缓存，因此下架、板块关闭和审核状态变化不会遗留可访问的
  旧正文缓存。

## 小程序与管理后台

- `TAB_VARIANT=4` 产物保留约骑、路线、消息、我的，且不注册论坛原生 Tab 页面；
  `TAB_VARIANT=5` 才加入论坛 Tab。两种产物的第一个原生 Tab 均为既有约骑首页，且保留
  V1 登录前置页。
- 论坛分包包含详情、发帖/编辑和我的内容；页面覆盖加载、空态、弱网、关闭、只读、待审、
  驳回、禁言和下架状态。
- 点赞使用即时行内状态和失败回滚，不重复 Toast；帖子与回复提交均有按钮锁和持久化幂等。
- 管理后台包含待审、审核异常、论坛举报、用户限制、板块和审计六个视图；审核、下架、
  举报处置、禁言/解禁和板块操作均要求二次确认或必填原因。

## 仍需外部门禁

以下事项不能由仓库代码单独证明，论坛正式开放前必须完成：

1. 提供商审核资质、真实密钥、图片审核能力和回调/超时指标在灰度环境验收；当前没有写入
   真实密钥，也没有修改 `.env`。
2. 运营确认首批受邀用户、四板块版规、人工审核值班表、举报处置 SLA 和申诉流程。
3. 微信开发者工具与真机验证 5 Tab 包、图片上传、弱网恢复、登录回跳和举报交互。
4. 使用预期峰值压测审核队列、数据库公开查询和上传链路，并接入生产监控告警。
5. 灰度前先开启 `forum.enabled` 做只读演练，确认治理后台可用后再显式开启
   `forum.write_enabled`；审核故障时关闭写开关，不能把异常视为放行。

在这些门禁完成前，应维持默认关闭或只读状态；不影响 V1 约骑、S2 路线和 S3 法规。
