# 摩搭子助手 V2.0 文档总览

> 文档基线：2026-07-31  
> 适用范围：V1.0 基本完成后的 V2.0 规划、设计、开发与验收  
> 状态：待产品、技术、运营联合评审

## 1. 本轮优化结论

V2.0 的目标不是一次性做完“摩托车全生态”，而是在不破坏 V1.0 核心约骑链路的前提下，验证“内容发现 → 社区互动 → 约骑转化”的增长闭环。

本轮将原计划收敛为三个可独立灰度、可量化验收的 MVP：

1. **路线精选 MVP**：官方/运营录入路线，用户浏览、收藏并跳转关联约骑。
2. **法规检索 MVP**：按分类和城市检索，所有内容具备官方来源、适用范围、有效状态和复核时间。
3. **论坛受控 MVP**：板块、发帖、一级回复、举报和后台审核；默认小流量开放。

以下能力不进入 V2.0 发布阻断范围，顺延至 V2.1：

- 用户路线 UGC、GPX/KML 上传与解析、路线评价、按轨迹距离搜索；
- 楼中楼、用户关注、@ 提及、二手交易、复杂富文本；
- 法规收藏、AI 问答、向量检索、社区贡献法规；
- 用户等级、公众号通知、完整深色模式和复杂动效。

## 3. 一致性规则

- 产品版本 V2.0 与 API 路径 `/api/v1` 是两个概念。新增且兼容的接口继续使用 `/api/v1`；只有破坏性契约变更才启用 `/api/v2`。
- Prisma Schema 是数据库结构唯一事实源；技术文档中的表结构用于评审，不直接作为生产 SQL 执行。
- 所有 P0 需求必须同时具备：用户故事、异常流程、埋点、验收标准、后台治理能力。
- 论坛和路线内容在审核失败或第三方审核不可用时不得自动公开，进入待审核队列。
- 法规内容必须显示来源链接、发布机构、适用地区、有效状态和最后复核时间；产品不提供法律意见。
- 每个里程碑必须通过自动化检查、手工验收和灰度指标门禁，不能只以“页面完成”作为完成标准。

- [ ] 明确法规内容负责人、审核人和月度复核机制。
- [ ] 为生产数据库完成备份、恢复演练和 V2.0 迁移演练。
- [ ] 确认 16 周资源：后端 1 人、小程序前端 1 人、管理后台 0.5 人、测试 0.5 人、产品/设计/内容按计划投入。

任一前置条件未满足时，应调整范围或发布时间，不以压缩测试周期补偿。
