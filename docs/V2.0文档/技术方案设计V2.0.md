# 摩搭子助手 — 技术方案设计 V2.0

> 文档版本：V2.0（优化版）  
> 更新日期：2026-07-31  
> 对应需求：[产品需求文档 PRD V2.0](./产品需求文档PRD_V2.0.md)

## 1. 现状与演进原则

当前仓库基线：NestJS 10 + Prisma 5 + MySQL 8 + Redis 7，Taro 4.2 + React 18 小程序，React 19 + Vite 8 + Ant Design 6 管理后台。V1.0 已有认证、用户、约骑、活动、消息、文件、举报、后台和定时任务模块；自动化测试基线不足。

V2.0 采用单体模块化演进，不拆微服务，不增加 Elasticsearch、消息队列等基础设施。原则如下：

1. 新模块可通过功能开关独立关闭；
2. 新增 API 保持兼容，继续使用 `/api/v1`；
3. Prisma Schema 和迁移文件是数据结构唯一事实源；
4. 先建立测试、日志、权限和审核基础，再开放 UGC；
5. 计数、缓存和搜索均可重建，MySQL 保存事实数据；
6. 第三方服务失败时安全降级，不绕过审核或权限。

## 2. 目标架构

```text
微信小程序 / 管理后台
        │ HTTPS + request-id
        ▼
Nginx / 云托管入口
        │
        ▼
NestJS 单体 API
├─ V1: auth/user/ride/activity/message/file/report/admin
├─ V2: route/regulation/forum/moderation/audit/feature-flag
├─ Prisma ─────────────── MySQL（事实数据）
├─ Redis ──────────────── 缓存、限流、幂等、热度
└─ 外部服务 ───────────── 微信、COS、内容安全
```

V2.0 不引入独立网关。Nginx 负责 TLS、请求体大小和基础限流，业务限流、认证、功能开关与审计由 NestJS 负责。

## 3. 横向基础能力（必须先交付）

### 3.1 配置与功能开关

在 `system_settings` 或独立 `feature_flags` 表维护：

- `route.enabled`、`regulation.enabled`、`forum.enabled`；
- `forum.publish_mode`（invite_only/gray/all）；
- 灰度百分比、白名单、限流参数；
- 配置版本和更新时间。

服务端决定最终可用性。原生 TabBar 的 4/5 项差异由构建环境生成两套 `app.config` 配置，不能依赖运行时远程删除 Tab；服务端开关用于兜底关闭页面和写接口。开关读取使用短 TTL 缓存，缓存失效时默认关闭高风险 UGC 功能。

### 3.2 结构化日志与请求 ID

- 使用 NestJS Logger 适配器输出 JSON；字段包括 `request_id`、用户/管理员 ID、路由、状态码、耗时和错误码；
- 接受可信入口传入的请求 ID，否则生成；响应头回传；
- 不记录 access token、openid、手机号、精确经纬度、富文本正文；
- 关键业务另外记录审计日志，不能只依赖应用日志。

### 3.3 统一错误与分页

错误响应保持现有统一外壳：

```json
{ "code": 42001, "message": "内容审核中", "data": null, "requestId": "..." }
```

列表统一使用游标：`limit`（默认 20，最大 50）+ `cursor`；返回 `items`、`nextCursor`、`hasMore`。游标编码排序键和 ID，避免只按时间造成重复/遗漏。

### 3.4 审计日志

新增 `operation_logs`：管理员 ID、动作、对象类型/ID、变更前后摘要、原因、IP、请求 ID、时间。日志追加写，不提供普通删除接口。

## 4. 数据模型

以下为逻辑模型，最终以 `backend/prisma/schema.prisma` 为准。所有关系在 Prisma 中声明外键与删除策略，时间使用数据库统一时区并以 ISO 8601 输出。

### 4.1 路线

| 模型 | 关键字段 | 约束/说明 |
|---|---|---|
| `Route` | title、cityCode、type、difficulty、distanceKm、durationMin、polyline、roadCondition、safetyNotice、status、sortWeight、maintainerId | V2.0 仅运营创建；发布字段完整校验 |
| `RoutePoint` | routeId、order、name、lat、lng、type、description | `routeId + order` 唯一；起点/终点必有 |
| `RouteFavorite` | userId、routeId、createdAt | `userId + routeId` 唯一 |
| `RouteRideLink` | routeId、rideId、source | 显式关联；可由运营维护 |

`polyline` 可保存抽稀后的坐标 JSON，限制点数和请求体大小；原始轨迹文件不在 V2.0 接收范围。路线“附近”按起点城市/城市码实现，不使用 Redis GEO 冒充完整轨迹距离。

### 4.2 法规

| 模型 | 关键字段 | 约束/说明 |
|---|---|---|
| `Regulation` | title、documentNo、issuer、authorityLevel、jurisdiction、status、publishedAt、effectiveAt、expiredAt、sourceUrl、lastVerifiedAt、reviewCycleDays | 当前可见版本与生命周期 |
| `RegulationRevision` | regulationId、version、summary、content、sourceSnapshot、changeNote、createdBy、reviewedBy | `regulationId + version` 唯一；发布后不可原地覆盖 |
| `RegulationTag` | name、normalizedName | 规范化关键词，独立表避免 JSON 难查询 |
| `RegulationFeedback` | regulationId、userId、type、description、status | 纠错处理队列 |

适用地区采用规范化地区码关联表；“全国”使用显式 scope，不以空数组表达。搜索在首批数百条规模下使用规范化标题/文号/发布机构/标签的前缀或包含匹配；上线前用真实中文数据验证。MySQL FULLTEXT 不作为 V2.0 中文模糊检索承诺。

### 4.3 论坛

| 模型 | 关键字段 | 约束/说明 |
|---|---|---|
| `ForumBoard` | name、description、sortOrder、status | 首批 4 个板块 |
| `ForumPost` | boardId、userId、title、content、status、moderationStatus、publishedAt、hotScore | 受限内容格式；软删除 |
| `ForumPostImage` | postId、fileRecordId、order、moderationStatus | 图片复用 V1 文件记录 |
| `ForumReply` | postId、userId、content、status、moderationStatus、publishedAt | V2.0 无 parentId |
| `ForumLike` | userId、targetType、targetId | 组合唯一约束，目标类型服务层校验 |
| `UserRestriction` | userId、type、reason、startsAt、endsAt、createdBy | 支持禁言期限与审计 |

举报复用 V1 `reports` 的 `content_type/content_id`，扩展允许 `forum_post`、`forum_reply`。若现有关系无法表达多态对象，不新增不可靠外键，服务层必须校验对象存在并保留快照摘要。

### 4.4 状态与计数

- 公共内容状态区分业务状态与审核状态，不使用一个整数混合表达；
- `likeCount/favoriteCount/replyCount/viewCount` 是派生值，写入事务中更新或通过任务对账；
- 每日运行计数对账任务，差异可自动修复并告警；
- 删除采用 `deletedAt`，公开查询统一过滤；审计/举报数据按保留策略保存。

## 5. API 设计

### 5.1 约定

- 查询：GET；创建：POST；完整/局部更新：PATCH；幂等关系使用 PUT/DELETE；
- 管理接口统一 `/api/v1/admin/...` 并使用管理员 JWT 与角色守卫；
- 写接口支持 `Idempotency-Key`（发帖、回复、批量导入等）；
- DTO 使用 `class-validator` 严格白名单；BigInt 统一序列化为字符串；
- OpenAPI 由代码生成，PRD 表格不是接口契约。

### 5.2 路线

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/routes` | 已发布路线列表，游标分页 |
| GET | `/api/v1/routes/:id` | 详情与收藏状态 |
| PUT/DELETE | `/api/v1/routes/:id/favorite` | 收藏/取消，幂等 |
| GET | `/api/v1/routes/:id/related-rides` | 有效关联约骑 |
| GET/POST | `/api/v1/admin/routes` | 管理列表/创建草稿 |
| GET/PATCH | `/api/v1/admin/routes/:id` | 详情/编辑 |
| POST | `/api/v1/admin/routes/:id/publish` | 发布 |
| POST | `/api/v1/admin/routes/:id/offline` | 下架，原因必填 |

### 5.3 法规

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/regulations` | 分类/地区/状态筛选 |
| GET | `/api/v1/regulations/search` | 关键词搜索 |
| GET | `/api/v1/regulations/:id` | 当前版本和来源 |
| POST | `/api/v1/regulations/:id/feedback` | 纠错反馈 |
| GET/POST | `/api/v1/admin/regulations` | 管理列表/创建草稿 |
| PATCH | `/api/v1/admin/regulations/:id` | 编辑草稿或创建修订 |
| POST | `/api/v1/admin/regulations/:id/submit-review` | 提交复核 |
| POST | `/api/v1/admin/regulations/:id/publish` | 复核后发布 |
| POST | `/api/v1/admin/regulations/imports` | CSV 导入任务 |

静态子路径必须在 `:id` 路由前注册，或使用明确前缀，避免把 `search` 解析为 ID。

### 5.4 论坛

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/forum/boards` | 可见板块 |
| GET/POST | `/api/v1/forum/posts` | 列表/提交审核 |
| GET/PATCH/DELETE | `/api/v1/forum/posts/:id` | 详情/编辑本人待审内容/删除本人内容 |
| GET/POST | `/api/v1/forum/posts/:id/replies` | 一级回复列表/提交审核 |
| DELETE | `/api/v1/forum/replies/:id` | 删除本人回复 |
| PUT/DELETE | `/api/v1/forum/posts/:id/like` | 点赞/取消 |
| GET | `/api/v1/admin/forum/moderation` | 审核队列 |
| POST | `/api/v1/admin/forum/moderation/:id/approve` | 审核通过 |
| POST | `/api/v1/admin/forum/moderation/:id/reject` | 驳回，原因必填 |
| POST | `/api/v1/admin/users/:id/restrictions` | 创建禁言 |

## 6. 内容审核与安全

### 6.1 审核流水线

```text
提交 → DTO/频率/权限校验 → 持久化为 PENDING
     → 文字审核 + 图片审核
     ├─ 全部通过：PUBLISHED
     ├─ 明确拒绝：REJECTED + 原因
     └─ 超时/异常：保持 PENDING，进入人工队列
```

审核任务必须可重试、可幂等、有最大重试次数和告警。禁止“审核服务异常即放行”。管理员人工放行需记录原因。

### 6.2 富文本与上传

- V2.0 论坛存储受限文本结构或经过服务端 allowlist 清洗的 HTML；不信任客户端清洗；
- 禁止脚本、事件属性、iframe、外链图片和未知协议；渲染端继续使用安全组件；
- 上传校验扩展名、MIME、文件头、大小和图片尺寸；COS Key 由服务端生成；
- 轨迹文件、压缩包和任意文档上传不在 V2.0 开放范围。

### 6.3 权限与防刷

- 每个修改/删除操作同时校验登录、资源所有权、资源状态和禁言状态；
- 频率限制采用用户 ID + IP/设备风险信号，阈值可配置；
- 对收藏、点赞、反馈、发帖和回复建立数据库唯一约束/幂等键；
- 管理后台敏感操作二次确认，发布法规和下架内容要求填写原因。

## 7. 缓存、热度与异步任务

- Redis 缓存仅用于公开列表、详情、功能开关和搜索建议；Key 包含版本，TTL 加随机抖动；
- 写入成功后删除相关缓存，删除失败由短 TTL 兜底；
- 热度分数包含时间衰减，并对浏览、点赞、回复贡献设上限，避免刷量主导；
- 浏览量按用户/设备时间窗口去重后异步聚合；
- 定时任务增加分布式锁，避免多实例重复执行；失败有日志、指标和手工补偿入口。

## 8. 前端与后台结构

```text
frontend/src/
├─ pages/routes/{index,detail}
├─ pages/regulations/{index,detail,feedback}
├─ pages/forum/{index,detail,create}
├─ components/{RouteCard,RegulationCard,PostCard,StatePanel}
└─ services/{routes,regulations,forum}.ts

admin/src/
├─ pages/{route-management,regulation-management,forum-moderation,operation-logs}.tsx
└─ api/{routes,regulations,forum,audit}.ts
```

新业务页面使用分包；原有约骑、消息、个人中心保留主包。原生 Tab 图标提供本地 PNG 普通/选中态，不使用 Emoji 作为正式图标。

## 9. 数据库迁移与发布

1. 不合并或改写已在任何共享/生产环境执行过的 V1.0 迁移；
2. 新建 V2.0 增量迁移，所有大表变更先评估锁表影响；
3. 在生产数据副本完成 `migrate deploy`、回滚/前滚和耗时演练；
4. 先部署兼容新旧 Schema 的后端，再迁移、再开放入口；
5. 种子数据通过可重复执行脚本导入，禁止把 50 条法规写进迁移 SQL；
6. 回滚优先关闭功能开关并回滚应用；已产生的业务数据不做破坏性自动删除。

## 10. 测试策略与质量门禁

| 层级 | 必测范围 |
|---|---|
| 单元测试 | 权限、状态机、热度、搜索规范化、法规有效性、审核决策 |
| API 集成 | 认证、幂等、游标、越权、审核失败、软删除、功能开关 |
| E2E 冒烟 | 登录→路线→关联约骑；法规搜索→来源；发帖→审核→公开→举报→下架 |
| 安全测试 | XSS、恶意文件、IDOR、限流绕过、管理员权限 |
| 性能测试 | 列表、详情、搜索、审核队列；使用接近生产的数据量 |
| 迁移测试 | 空库、V1 快照、重复执行、失败恢复 |

CI 至少执行：后端 lint/build/test、前端 typecheck/build、后台 lint/build、Prisma validate、迁移一致性检查。新增核心 Service 的分支覆盖率目标 ≥80%，全仓覆盖率只作为趋势指标。

## 11. 可观测与告警

关键指标：API QPS/错误率/P95/P99、数据库慢查询、Redis 错误、审核成功率/超时率/积压、定时任务失败、法规复核逾期、论坛举报处理 SLA。

告警必须包含环境、模块、错误摘要、请求 ID、影响范围和排查链接。上线前验证告警能真正触达值班人。

## 12. 依赖与风险决策

| 风险 | 技术决策 |
|---|---|
| 论坛资质未确认 | `forum.enabled=false`，不部署入口但保留已完成代码 |
| 内容安全服务不可用 | 新内容保持 PENDING；公开内容不受影响 |
| 法规来源失效 | 标记待复核并从推荐位移除，不自动删除历史版本 |
| 搜索效果不足 | 先优化字段与同义词；达到规模阈值后再评估专用搜索 |
| 包体积超预算 | 分包、依赖分析、图片资源外置；不为新模块复制 UI 库 |
| 人力不足 | 论坛顺延，优先保证路线、法规和基础质量能力 |
